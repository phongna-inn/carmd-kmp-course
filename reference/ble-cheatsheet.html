Callbacks into a Kotlin Flow

// Android: the adapter is the callbackFlow
override fun scan(): Flow<Device> = callbackFlow {
    val callback = object : ScanCallback() {
        override fun onScanResult(type: Int, r: ScanResult) { trySend(r.toDevice()) }
        override fun onScanFailed(code: Int) { close(ScanException("…$code")) }
    }
    scanner.startScan(null, settings, callback)
    awaitClose { scanner.stopScan(callback) }      // mandatory: runs on cancel
}

// iOS: Swift can't build a Flow (SKIE converts Flow → AsyncSequence only),
// so Kotlin in iosMain builds it and Swift feeds it
fun scanFlow(radio: IosRadio): Flow<Device> = callbackFlow {
    radio.startScan(ScanFeed(this))                // Swift calls feed.heard / feed.failed
    awaitClose { radio.stopScan() }
}
// Swift: func scan() -> SkieSwiftFlow<Device> { scanFlow(radio: self) }

Traps

  • Simulator and emulator. The iOS Simulator has no BLE radio (.unsupported). The Android emulator's Bluetooth is simulated: it never hears your Mac. Real peripherals need real phones.
  • The iOS delegate is weak. Keep the delegate alive (here: Koin holds the adapter, which is its own delegate), or callbacks go nowhere.
  • Android scan throttling. Too many scan starts in a short time and the next one silently returns nothing; logcat says "scanning too frequently". We hit it with six starts in about ten seconds.
  • Check the permission before the radio. On iOS, creating the manager is a first use of Bluetooth and can show the prompt.
  • Always time-limit a scan. "Never scan on a loop, and always set a time limit on your scan."
