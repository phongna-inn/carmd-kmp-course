Shared ViewModels Across Four Tracks

Compressed from Lesson 08 (the shared ViewModel, owning it, the hand-written bridge) and Lesson 09 (SKIE). Built and checked with Kotlin 2.4.20, SKIE 0.10.15, AndroidX Lifecycle 2.11.0, kotlinx-coroutines 1.11.0, AGP 9.4.1, Xcode 26.2 (Swift 6 mode).

The rules

  1. Work lives in the ViewModel, the UI only observes. Long-running work runs in viewModelScope; it stops when the ViewModel is cleared, not when the UI stops collecting.
  2. One immutable UI state, exposed as StateFlow. State goes down, events (function calls) go up.
  3. Sealed types for modes (Idle / Scanning / Finished), so impossible combinations can't be written and every when/switch is exhaustive.
  4. Errors and messages are state: errorMessage: String? plus errorShown(). No Channel/SharedFlow "events".
  5. Input stays in the UI (text being typed) and is passed as an argument when it's needed: startScan(filter).
  6. Collect only while visible; every new collector gets the current state first.

The shape (commonMain)

data class DeviceListUiState(val scan: ScanState = ScanState.Idle, val errorMessage: String? = null)
sealed interface ScanState {
    data object Idle : ScanState
    data class Scanning(val found: List<Device>) : ScanState
    data class Finished(val found: List<Device>) : ScanState
}

class DeviceListViewModel(private val scanner: FakeDeviceScanner) : ViewModel() {
    private val _uiState = MutableStateFlow(DeviceListUiState())       // backing property
    val uiState: StateFlow<DeviceListUiState> = _uiState.asStateFlow()

    fun startScan(filter: String) {
        _uiState.update { it.copy(scan = ScanState.Scanning(emptyList())) }   // state first…
        viewModelScope.launch { … }                                            // …then the slow part
    }
    fun errorShown() = _uiState.update { it.copy(errorMessage = null) }

    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory { initializer { DeviceListViewModel(FakeDeviceScanner()) } }
    }
}
  • update { it.copy(…) }, never mutate. Put copies of collections in state (found.toList()): StateFlow skips values equals to the current one.
  • withTimeoutOrNull(t) { … } stops a never-ending flow and returns null, without throwing.
  • Catch your own exception types only. catch (e: Exception) also swallows CancellationException.

Android rotation: the ViewModel survives and the new screen re-collects. Process death: the ViewModel is lost (SavedStateHandle to keep it, out of scope).

iOS: owning a shared ViewModel

// iosMain: ViewModelResolver.kt (Swift can only pass an ObjC class)
@OptIn(BetaInteropApi::class) @Throws(IllegalArgumentException::class)
fun ViewModelStore.resolveViewModel(modelClass: ObjCClass, factory: ViewModelProvider.Factory): ViewModel {
    val vmClass = getOriginalKotlinClass(modelClass) as? KClass<ViewModel>
    require(vmClass != null) { "The modelClass parameter must be a ViewModel type." }
    return ViewModelProvider.create(this, factory)[vmClass]
}

// Swift: ViewModelOwner.swift
final class ViewModelOwner {
    private let store = ViewModelStore()
    func viewModel<VM: ViewModel>(factory: any ViewModelProviderFactory) -> VM {
        try! store.resolveViewModel(modelClass: VM.self, factory: factory) as! VM   // lesson: do/catch + fatalError
    }
    deinit { store.clear() }   // onCleared() + cancels viewModelScope
}

No owner means no clear(): the ViewModel's coroutines outlive the screen (reproduced: an orphaned scan kept finding devices). Don't call ViewModelStore.put; it's @RestrictTo. Keep @State defaults cheap: SwiftUI re-instantiates them whenever it recreates the view.

Traps

  • Imperative render(): a scan now starts as Scanning([]), so "is the list empty?" alone painted "Scanning…" red. Derive each widget from the mode first.
  • XML: collect on viewLifecycleOwner, not the Fragment, so render never touches dead views. Dismiss a dialog in onDestroyView with dismiss(), which doesn't fire the cancel listener, so the error stays in state across rotation.
  • SwiftUI .task re-runs on every return: fine for observing, wrong for starting work.
  • UIKit Task { for await … } captures self: cancel it in viewDidDisappear, and cancel any old one before starting a new one.
  • After SKIE, uiState's line in Shared.h is unchanged; the typed API is in Shared.apinotes and shared/build/skie/…/swift/generated/.
  • Never check warnings with gradlew -q; the Kotlin/Native link warnings appear inside the Xcode build.
