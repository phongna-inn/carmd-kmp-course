Layers, Ports, DI and Tests

Compressed from Lesson 06. Built and checked with Kotlin 2.4.20, Koin 4.2.2, kotlinx-coroutines(-test) 1.11.0, Turbine 1.2.1, AGP 9.4.1, Xcode 26.2.

The rules

  1. Dependencies point toward the domain. domain imports no other layer. presentation imports domain. data implements domain's ports. Only di knows every layer.
  2. A port is an interface in commonMain, written in the app's terms (Flow<Device>, never ScanResult). Adapters implement it: in commonMain, in androidMain, in Swift, or in commonTest (fakes). Use an interface, not expect/actual, whenever you need more than one implementation or a Swift one.
  3. Constructor injection everywhere. Classes receive dependencies and never build them. Only the composition root (di/) calls the constructors or names an adapter.
  4. A use case is one app rule: VerbNounUseCase, operator fun invoke, no mutable state kept between calls.
  5. Lookups (KoinComponent, get()) only at the edges: classes Koin doesn't create (the iOS ViewModel factory). Never in ViewModels, use cases or adapters.
  6. Tests use constructors and fakes, not the container. One extra test checks that the Koin graph builds.

Port, use case, adapter

interface BleScanner { fun scan(): Flow<Device> }       // cold, never-ending: collect = start, cancel = stop

class ScanForDevicesUseCase(private val scanner: BleScanner) {
    operator fun invoke(filter: String): Flow<Device> = flow {
        val wanted = filter.trim()
        val seen = mutableSetOf<String>()                   // per collection, never a property
        scanner.scan().collect { d ->
            if (d.name.contains(wanted, ignoreCase = true) && seen.add(d.id)) emit(d)
        }
    }
}

class SimulatedBleScanner : BleScanner { override fun scan() = flow { while (true) for (d in SampleDevices.all) { delay(300); emit(d) } } }

Test recipe (commonTest)

// shared/build.gradle.kts
kotlin { android { withHostTest {} } }                      // else Android tests silently never run
commonTest.dependencies {
    implementation(kotlin("test"))
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.11.0")
    implementation("app.cash.turbine:turbine:1.2.1")
}

@OptIn(ExperimentalCoroutinesApi::class)                    // else w: needs opt-in
class SomeViewModelTest {
    @BeforeTest fun setUp() { Dispatchers.setMain(StandardTestDispatcher()) }   // in setUp, not a property
    @AfterTest fun tearDown() { Dispatchers.resetMain() }

    @Test fun something() = runTest {                       // shares Main's virtual clock
        vm.uiState.test {                                   // Turbine
            assertEquals(…, awaitItem())                    // 3 s wall-clock timeout per item
            // unconsumed items at the end fail the test
        }
        testScheduler.runCurrent()                          // run what's ready, clock unchanged
        testScheduler.currentTime                           // virtual ms elapsed
    }
}

./gradlew :shared:allTests runs testAndroidHostTest (JVM, JUnit 4) and iosSimulatorArm64Test (Kotlin/Native runner). Check that both tasks appear: a green build only means nothing failed.

Fakes over mocks. A fake implements the port with test controls (hear(…), failure, scansStarted). Use a Channel(UNLIMITED) so nothing sent before the collector subscribes is lost. A completing flowOf(…) fake suits a pure use-case test with toList().

Mutation check. Break one rule in the production code and run the tests. If they stay green, nothing protects that rule.
