The Hexagon, Koin and Tests

Compressed from Lesson 10 (the hexagon, DI by hand) and Lesson 11 (tests, Koin), plus Lesson 17's rule for services that need each other. Built and checked with Kotlin 2.4.20, Koin 4.2.2, kotlinx-coroutines(-test) 1.11.0, Turbine 1.2.1, AGP 9.4.1, Xcode 26.2.

The rules

  1. The app core imports nothing from Android, iOS or any framework: only Kotlin's standard library, kotlinx.coroutines and its own packages. No androidx, no platform.*, no Koin or Ktor.
  2. One rule for where code goes. UI code goes in the screen. A rule of the app goes in a service. Anything that talks to a platform, a library or the network goes in an outbound adapter, behind an outbound port.
  3. One inbound port per capability (DeviceScanning), not per action. New actions are new methods on it.
  4. Outbound ports are named in the app's terms (BleScanner, LogUploader; never ApiClient, ScanResult, CBPeripheral). Use an interface, not expect/actual: ports need several implementations, one of them in Swift.
  5. ViewModels talk only to inbound ports. They never see a service class or an outbound port.
  6. Constructor injection everywhere. In the app's code, only the composition root (di/) calls the constructors or names a service or an adapter. Tests build what they test themselves (rule 8).
  7. Lookups (KoinComponent, get()) only at the edges: classes Koin doesn't create (the iOS ViewModel factory). Never in the app core, ViewModels or adapters.
  8. Tests drive inbound ports, with test doubles built by constructor, never through the container. One extra test checks that the Koin graph builds.
  9. Services don't know each other. When one capability needs something another capability holds, its service asks through an outbound port named in its own terms, and a small bridge adapter in the shared code (adapter.outbound) implements that port by calling the other capability's inbound port. The bridge holds no rules: a rule it seems to need belongs in one of the two services. (Lesson 17)

Port, service, adapter

interface DeviceScanning { fun scan(nameFilter: String): Flow<Device> }   // what the app offers
interface BleScanner { fun scan(): Flow<Device> }                       // what the app needs; collect = start, cancel = stop

class ScanningService(private val scanner: BleScanner) : DeviceScanning {
    override fun scan(nameFilter: String): Flow<Device> = flow {
        val wanted = nameFilter.trim()
        val seen = mutableSetOf<String>()                   // per scan, never a property
        scanner.scan().collect { d ->
            if (d.name.contains(wanted, ignoreCase = true) && seen.add(d.id)) emit(d)
        }
    }
}

class DeviceListViewModel(private val scanning: DeviceScanning) : ViewModel()   // the port, nothing else

single<ConnectionStatus> { SessionConnectionStatus(get()) }          // in appModule: the one DeviceSession

Not a direct call to DeviceSession (a service would call an inbound port), not SessionService implementing the port (an outbound port implemented by a service), not a shared state holder or domain events. Inbound ports are called by inbound adapters and by bridge adapters.

Test recipe (commonTest)

// shared/build.gradle.kts
kotlin { android { withHostTest {} } }                      // else the JVM tests silently never run
commonTest.dependencies {
    implementation(kotlin("test"))
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.11.0")
    implementation("app.cash.turbine:turbine:1.2.1")
}

// A service: through its inbound port, with a fake behind the outbound port.
private val radio = FakeBleScanner()
private val scanning: DeviceScanning = ScanningService(radio)
@Test fun rule() = runTest {
    scanning.scan(nameFilter = "").test {                   // Turbine
        radio.hear(obd, heart, obd)                         // the test plays the radio
        assertEquals(obd, awaitItem())                      // 3 s wall-clock timeout per item
        assertEquals(heart, awaitItem())
    }                                                       // cancels, then fails on unconsumed items
}

// A ViewModel: against a test implementation of the inbound port.
@OptIn(ExperimentalCoroutinesApi::class)                    // setMain, resetMain, currentTime
class SomeViewModelTest {
    @BeforeTest fun setUp() { Dispatchers.setMain(StandardTestDispatcher()) }   // in setUp, not a property
    @AfterTest fun tearDown() { Dispatchers.resetMain() }
    // runTest shares Main's virtual clock: timeouts fire at once
    // testScheduler.runCurrent(): run what's ready, clock unchanged
    // testScheduler.advanceTimeBy(d): move the clock, running what's due before the new time
    // testScheduler.currentTime: virtual ms elapsed
}

More than one graph test? Close each koinApplication after its test (@AfterTest fun closeKoin() { app.close() }). appModule is one object, and Koin 4.2.2 keeps a single's instance in the module's definition, so without close() a later test can get an earlier test's instances (Lesson 17).

./gradlew :shared:allTests runs testAndroidHostTest (JVM, JUnit 4) and iosSimulatorArm64Test (Kotlin/Native's runner). Check that both tasks appear: a green build only means nothing failed.

Test doubles, not mocks. A fake is an outbound adapter written for tests, with controls (hear(…), failure, isScanning). A test implementation of an inbound port (TestDeviceScanning: find(…), failure, filters) stands in for the whole app core in a ViewModel test. Both use a Channel(UNLIMITED), so nothing sent before the collector starts is lost, and both flows never complete, like a real scan.

Mutation check. Break one rule in the production code and run the tests. If they stay green, nothing protects that rule.
