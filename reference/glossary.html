Course Glossary

Every lesson uses these terms with exactly these meanings. Each entry names the lesson that introduces it.

Course terms

Milestone (m00…m10, e1…e3)
The finished demo state a lesson produces. Each lesson's agent brief starts from the previous milestone. (Plan)
UI track
Your choice of UI stack per platform: Android XML or Compose, iOS UIKit or SwiftUI. The default is Compose + SwiftUI. (Plan)
Agent brief
The copy-paste block at the end of each lesson that tells a coding agent what to build and how to check it. (Plan)
Unaided exercise

Language and concurrency

Data class (Kotlin)
A class for holding values; the compiler generates equals, hashCode, toString, copy. (01)
Sealed interface (Kotlin) / enum with associated values (Swift)
A closed set of cases known at compile time, so when/switch over it must be exhaustive. Used for every UI state. (01)
Extension
Adding members to an existing type without subclassing it; statically resolved. (01)
Value type / reference type
A value type (Swift struct) is copied on assignment; a reference type (class) is shared. (01)
Optional / nullable type
T?: a type that may hold no value. Must be unwrapped or given a fallback before use. (01)
Coroutine
A suspendable unit of work in Kotlin, started by a builder such as launch. (01)
Suspend function
A Kotlin function that can pause without blocking a thread; callable only from a coroutine or another suspend function. (01)
Coroutine scope / structured concurrency
A scope owns the coroutines launched in it; cancelling the scope cancels them all. (01)
Flow (cold)
An async stream whose producer runs only when collected, once per collector. (01)
StateFlow (hot, conflated)
A flow that always holds one current value; collectors see only the latest value, not a backlog. (01)
Conflation
Dropping intermediate values so a slow consumer sees only the most recent one. (01)
Backing property
Private mutable state exposed as a public read-only view (_state / state; Swift private(set)). (01)
AsyncSequence / AsyncStream (Swift)
Swift's async stream protocol and its push-based implementation (yield, finish), consumed with for await. (01)
Task (Swift)
A unit of async work. A bare Task { } is unstructured: nothing cancels it automatically. (01)
Main actor (@MainActor)
The isolation domain for UI work; code marked with it runs only there, and the compiler enforces that. (01)

Platform

Activity (Android)
An app entry point with a window and a lifecycle (onCreate … onDestroy). The course app has one. (02)
Context (Android)
Your handle to the system: resources, system services, starting components. An Activity is a Context. (02)
Intent (Android)
A message asking the OS to start something; explicit (a named class) or implicit (any app that can handle an action). (02)
Manifest / Info.plist
The declaration file each OS reads before running your code: components, permissions, metadata, permission-prompt strings. (02)
Configuration change (Android)
Rotation, dark mode, font size, etc.; by default destroys and recreates the Activity. (02)
compileSdk / minSdk / targetSdk
APIs you can see / oldest Android that can install / runtime behaviour you opt into. (02)
Scene / scene phase (iOS)
One app window and its app-level state: active, inactive, background. The level to hook for "is the app in front?" (02)
View lifecycle (iOS)
Appear/disappear events for one screen inside the app (onAppear, viewWillAppear, …); not fired by backgrounding. (02)
Logger / Logcat
Apple's structured logging API (subsystem + category) / Android's log viewer for Log.d(tag, msg). (02)

Kotlin Multiplatform

KMP (Kotlin Multiplatform)
Compiling one Kotlin codebase to several platforms; here the shared core of the Android and iOS apps. (03)
Shared module (:shared)
The Gradle module holding the shared Kotlin. Android depends on it as a library; iOS consumes it as a framework. (03)
Target
A platform the compiler builds for: android, iosArm64 (devices), iosSimulatorArm64 (simulator on Apple silicon). (03)
Source set
A folder of Kotlin code plus the targets it compiles to, which decides the APIs it may call: commonMain, androidMain, iosMain. (03)
Intermediate source set
A source set shared by some but not all targets, e.g. iosMain for both iOS targets. Created by Kotlin's default hierarchy. (03)
expect / actual
A declaration without a body in common code (expect) and its required per-platform implementation (actual). For small facts; behaviour goes behind a port. (03)
Kotlin/Native
The Kotlin compiler backend that produces native binaries, used for the iOS targets; exposes Apple frameworks to Kotlin as platform.*. (03)
Framework (Apple)
A bundle of a compiled binary plus headers. The shared module becomes Shared.framework, imported in Swift as import Shared. (03)
Objective-C header (Shared.h)
The generated description of the shared API that Swift actually reads; the place to look up Swift names such as Platform_iosKt. (03)
Direct integration
Wiring the framework into Xcode with a script build phase that runs :shared:embedAndSignAppleFrameworkForXcode on every build. (03)

Declarative UI

Imperative UI / declarative UI
Imperative: handlers mutate widget objects one property at a time (XML Views, UIKit). Declarative: you describe the screen for a given state and the framework applies the changes (Compose, SwiftUI). (04)
UI state
The values a screen is drawn from, e.g. isScanning and devices. The screen is a function of it. (04)
Single source of truth
Each piece of state lives in exactly one place; everyone else reads it or asks it to change. (04)
Derived state
A value computed from state on every render (status text, enabled flags) instead of stored. (04)
Recomposition / body re-evaluation
The framework re-running UI code when state it read changes (Compose / SwiftUI). Frequent, skippable, order not guaranteed, so UI code must be side-effect free. (04)
render()
On imperative tracks, the one function that copies all state into all widgets; every handler ends with it. (04)
Side effect
Work that changes something outside the UI function (starting a scan, writing a file). Belongs in event callbacks or lifecycle-bound effects (LaunchedEffect, .task), never in the UI function. (04)
State hoisting / unidirectional data flow
Moving state up to a caller and passing down values plus event lambdas: state goes down, events go up. A SwiftUI Binding is the two-way form. (04)
Stable key (item identity)
A unique, unchanging id per list item (the device id), used by lists to match rows across updates. Never an index. (04)
Back stack / route
The stack of screens; Back pops one. A route is the small, saveable value pushed to open a screen (DeviceDetail(id)), carrying ids, not objects. (04)
Main thread (UI thread)
The one thread allowed to touch UI. Don't block it; don't update UI from elsewhere. Swift: @MainActor. (04)

Shared ViewModels and Kotlin↔Swift

ViewModel
A screen-level state holder that outlives the screen's views: it survives Android rotation and lives until its owner is gone. AndroidX's ViewModel is multiplatform, so ours lives in commonMain. (05)
ViewModelStore / ViewModelStoreOwner
The container that keeps ViewModels, and whatever holds that container (an Activity, Fragment or navigation entry). Clearing the store clears its ViewModels. iOS has no built-in owner. (05)
ViewModelOwner (course term)
Our Swift class that plays ViewModelStoreOwner on iOS: it resolves ViewModels from a store and clears the store in deinit. (05)
Cleared (ViewModel)
The end of a ViewModel's life: onCleared() runs and viewModelScope is cancelled, which stops its work. (05)
viewModelScope
The coroutine scope of a ViewModel; everything launched in it is cancelled when the ViewModel is cleared. Runs on Dispatchers.Main.immediate. (05)
ViewModel factory
Tells the platform how to construct a ViewModel with arguments (viewModelFactory { initializer { … } }), because the platform, not your code, creates it. (05)
Lifecycle-aware collection
Collecting a flow only while the screen is visible: collectAsStateWithLifecycle, repeatOnLifecycle(STARTED), SwiftUI .task, UIKit viewWillAppear/viewDidDisappear. Stopping collection doesn't stop the ViewModel's work. (05)
User message as state
A one-time message (an error dialog) kept in UI state until the UI reports it shown (errorShown()), instead of being sent as an event that can be lost. (05)
Impossible state
A combination of values the types allow but that means nothing (scanning with no result list). A sealed type removes it. (05)
Bridge (interop)
Code that adapts a Kotlin API into a Swift-friendly one, e.g. Part A's StateFlowWatcher. Hand-written, or generated by SKIE. (05)
SKIE
Touchlab's Kotlin compiler plugin that generates Swift into the framework: flows as typed AsyncSequences, sealed types via onEnum(of:), suspend as async. Pinned to exact Kotlin versions. (05)
onEnum(of:)
SKIE's function that turns a Kotlin sealed value into a generated Swift enum, so switch is exhaustive. (05)
Swift export
JetBrains' upcoming Kotlin→Swift API export (Alpha), meant to replace the Objective-C header. (05)
Sendable (Swift)
A type safe to pass between concurrency domains. Kotlin classes arrive without it, so Swift 6 rejects them in @Sendable closures. (05)
api / implementation (Gradle)
api exposes a dependency to modules that use yours; needed when its types appear in your public API (ViewModel, StateFlow). implementation keeps it private. (05)
export (framework)
Including a dependency's public API in the iOS framework header, so Swift can use its classes under clean names. (05)

Architecture, DI and testing

Layer: presentation · domain · data
Groups of code with one kind of responsibility. Presentation: ViewModels and UI state. Domain: models, ports and use cases, the app's own rules. Data: adapters that provide what the ports promise. In the course each layer is a package in shared. The native screens sit on top. (06)
Dependency rule
Dependencies point toward the domain. The domain imports no other layer, and only the composition root knows every layer. (06)
Port
An interface in commonMain, owned by the code that needs it and written in the app's terms (BleScanner). Platform code implements it. (06)
Adapter
One concrete implementation of a port: simulated, a platform radio (Kotlin in androidMain, or Swift), a library (Kable), or a test fake. (06)
Use case
A domain class for one app rule, named VerbNounUseCase and called through operator fun invoke. It keeps no mutable state between calls. (06)
Dependency injection (DI) / constructor injection
A class receives its dependencies (through its constructor) instead of building them. The app decides what to pass. (06)
Composition root
The one place that builds the object graph and names the adapters: AppContainer by hand, then Koin's appModule. (06)
Service locator
A registry that classes ask for their dependencies (KoinComponent + get()). It hides what a class needs, so the course allows it only at the edges. (06)
DI container / Koin module
A library that builds the graph from declarations (single: one instance, factory: new each time, viewModel: new, then kept by the store). It works out the order, but checks it only at run time. (06)
Test double / fake
An object a test uses in place of a real dependency. A fake is a working but simplified implementation (FakeBleScanner), and Android prefers fakes over mocks. (06)
Test dispatcher / virtual time
StandardTestDispatcher queues coroutines on a test scheduler whose clock skips delays. Dispatchers.setMain puts it under viewModelScope, and runTest shares its clock. (06)
Turbine
Cash App's library for testing flows: flow.test { awaitItem() }, with a 3 s wall-clock timeout. Unconsumed items fail the test. (06)
Host test
A test that runs on the development machine's JVM (testAndroidHostTest), as opposed to a device. With the Android-KMP plugin it's off until withHostTest {}. (06)
Mutation check
Deliberately breaking one rule in production code to see whether any test fails. If none does, no test protects that rule. (06)
