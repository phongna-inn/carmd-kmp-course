Why this matters: a background monitor hooked to the wrong lifecycle never notices that the app went to the background. iOS splits "is the app in front?" from "is this screen showing?", and only one of them tells you. Today you build a tiny iOS app that logs both kinds of event, then watch the logs while you poke it.

Primary sources Apple's Managing your app's life cycle, plus SwiftUI's ScenePhase.

2. Info.plist

Info.plist is the app's metadata dictionary: display name, version, launch screen, and later the usage-description strings that iOS shows in permission prompts (Apple: Information property list). Requesting Bluetooth without NSBluetoothAlwaysUsageDescription doesn't get you a polite denial; the app is terminated. You'll add it in Lesson 12.

With XcodeGen you don't write Info.plist by hand. The info section of project.yml holds its contents, and xcodegen generate writes the file.

The SwiftUI track needs nothing beyond a display name and a launch screen. SwiftUI's App creates its own scene.

The UIApplicationSceneManifest entry is how UIKit finds your scene delegate: it names the SceneDelegate class that runs each window. Without it, the scene delegate never runs and no window appears.

3. Two lifecycles, not one

Android tied "is this screen visible?" and "is the app in front?" to the same Activity callbacks. iOS separates them:

  • App/scene level: is the app's window active, inactive, or in the background? SwiftUI exposes this as scenePhase.UIKit delivers it to the scene delegate (sceneDidBecomeActive, sceneDidEnterBackground, …).
  • View level: did this screen appear or disappear inside the app? onAppear / onDisappear.viewDidLoad, viewWillAppear, viewDidAppear, viewWillDisappear, viewDidDisappear.

Logging uses Apple's Logger, the counterpart of Android's Log.d(TAG, …): subsystem + category ↔ tag. Output shows in Xcode's console, where you can filter on Lifecycle. The subsystem is any string you choose (here com.example.lesson04, not the bundle ID), so filter on it or on the category. Each excerpt below shows only the lines its notes explain, and the complete files are in Full files at the end.

  1. @main struct … : App is the entry point. There's no AppDelegate; SwiftUI owns the app object.
  2. @Environment(\.scenePhase) reads a value SwiftUI provides. Watching it with .onChange(of:) at the Scene level gives you the app-level lifecycle.
  3. Each log message is a fixed string per case. Logger redacts interpolated strings and objects by default and can show them as <private> in stored logs. Fixed strings never are.
  4. @unknown default handles phases Apple may add in future iOS versions. ScenePhase isn't a closed enum the way your own are.
  5. onAppear/onDisappear are attached to views. They report what happens inside the app (navigation), not whether the app is in front.
  1. AppDelegate owns process-level events. The scene configuration names the delegate class (via Info.plist) that runs each window.
  2. SceneDelegate creates the window and its root: a UINavigationController, which gives you push/pop navigation and a back button.
  3. The four scene… methods are the app-level lifecycle you'd hook a background monitor into.
  4. The UI is built in code (no storyboard): create a view, add it, constrain it. [weak self] avoids a retain cycle between the view controller and its own button's action.
  5. The view controller's callbacks are the view-level lifecycle. viewDidLoad runs when the screen's view is first created. The four appear/disappear callbacks run each time navigation shows or hides the screen (a push or a pop). Pressing Home fires none of them (section 4). Each override calls super first.
  6. Info.plist needs the UIApplicationSceneManifest entry from project.yml, shown in section 2. Without it the SceneDelegate never runs.

UIKit vs SwiftUI · what changed and whyUIKit splits the lifecycle across three objects you write yourself (AppDelegate, SceneDelegate, view controllers). SwiftUI turns both levels into state you observe: scenePhase for the app, and onAppear/onDisappear modifiers for views. The two-lifecycle model underneath is the same.

Gotcha · backgrounding fires no view callbacks Press Home and no view-level "disappear" callback fires. Only the scene/app level changes. View callbacks report navigation inside the app, not the app leaving the screen. So a background monitor (Lesson 18) built on view callbacks would silently never notice the app going away: hook the app/scene level. Also note the order during navigation: the new view's onAppear runs before the old view's onDisappear.Also note the order during navigation: the two screens' callbacks interleave (old viewWillDisappear, new viewWillAppear, old viewDidDisappear, new viewDidAppear). Don't write code that depends on either screen's callbacks running first.
Gotcha · no callback when a suspended app is killed Swiping the app away in the app switcher, or the OS reclaiming memory, ends a suspended app with no notice at all. applicationWillTerminate isn't called for suspended apps (Apple docs). Save anything important when you enter the background, not "on exit".

Retrieval checks

Answer from memory, without scrolling up.

You press Home on the detail screen. Which events fire?

Backgrounding doesn't change what's on the navigation stack, so no view callback runs.

Which file holds the text iOS shows in a Bluetooth permission prompt?

Usage descriptions are Info.plist keys. A missing one terminates the app when the permission is requested.

Where would a background monitor hook in to learn that the app left the screen?

Backgrounding is an app/scene event. The view level only reports navigation inside the app.

ScenePhase can gain new cases in a future iOS. What does @unknown default add to a switch over it?

With plain default, a newly added case would be handled silently. @unknown default keeps the exhaustiveness check for the cases you know.

Sources/Lesson04App.swift 
import SwiftUI
import os

let lifecycleLog = Logger(subsystem: "com.example.lesson04", category: "Lifecycle")

@main
struct Lesson04App: App {
    @Environment(\.scenePhase) private var scenePhase

    init() {
        lifecycleLog.notice("App init")
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { _, newPhase in
            switch newPhase {
            case .active: lifecycleLog.notice("scenePhase → active")
            case .inactive: lifecycleLog.notice("scenePhase → inactive")
            case .background: lifecycleLog.notice("scenePhase → background")
            @unknown default: lifecycleLog.notice("scenePhase → unknown")
            }
        }
    }
}

Sources/SceneDelegate.swift 
import UIKit

final class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?

    func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
               options connectionOptions: UIScene.ConnectionOptions) {
        guard let windowScene = scene as? UIWindowScene else { return }
        let window = UIWindow(windowScene: windowScene)
        window.rootViewController = UINavigationController(rootViewController: ViewController())
        window.makeKeyAndVisible()
        self.window = window
        lifecycleLog.notice("scene willConnect")
    }

    func sceneWillEnterForeground(_ scene: UIScene) { lifecycleLog.notice("sceneWillEnterForeground") }
    func sceneDidBecomeActive(_ scene: UIScene) { lifecycleLog.notice("sceneDidBecomeActive") }
    func sceneWillResignActive(_ scene: UIScene) { lifecycleLog.notice("sceneWillResignActive") }
    func sceneDidEnterBackground(_ scene: UIScene) { lifecycleLog.notice("sceneDidEnterBackground") }
}
Sources/ViewController.swift 
import UIKit

final class ViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        lifecycleLog.notice("ViewController viewDidLoad")
        title = "Lifecycle"
        view.backgroundColor = .systemBackground

        let button = UIButton(type: .system)
        button.setTitle("Open detail screen", for: .normal)
        button.addAction(UIAction { [weak self] _ in
            self?.navigationController?.pushViewController(DetailViewController(), animated: true)
        }, for: .touchUpInside)
        button.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(button)
        NSLayoutConstraint.activate([
            button.centerXAnchor.constraint(equalTo: view.centerXAnchor),
            button.centerYAnchor.constraint(equalTo: view.centerYAnchor),
        ])
    }

    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        lifecycleLog.notice("ViewController viewWillAppear")
    }

    override func viewDidAppear(_ animated: Bool) {
        super.viewDidAppear(animated)
        lifecycleLog.notice("ViewController viewDidAppear")
    }

    override func viewWillDisappear(_ animated: Bool) {
        super.viewWillDisappear(animated)
        lifecycleLog.notice("ViewController viewWillDisappear")
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        lifecycleLog.notice("ViewController viewDidDisappear")
    }
}
