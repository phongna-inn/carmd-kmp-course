1. What you'll build

You'll build one app, the Native Device Monitor, for Android and iOS, on top of shared Kotlin Multiplatform (KMP) code. The app:

  • asks for the Bluetooth permissions it needs, and handles every answer;
  • scans for Bluetooth Low Energy (BLE) devices and filters them by name;
  • connects to a device, lists its services and characteristics, reads a value and subscribes to notifications;
  • shows the phone's battery, network and Bluetooth status;
  • runs a background monitor that logs that status on an interval, as often as each OS allows; neither guarantees exact timing in the background.

The screens are native: Compose on Android and SwiftUI on iOS by default. Everything else that isn't tied to a platform is shared Kotlin. The app is organised around an app core in the shared code, with adapters on both sides, the shape in the diagram below. You'll build it up from Lesson 10; for now, only notice the pieces and their colours.

2. How the course works

  • Four weeks, one lesson a day. There are 20 core lessons, each at most about 2.5 h on the default track, and each ends at a natural stop: a passing build or a finished exercise. Lesson 00 counts for no day.
  • One app, growing. From Lesson 05 on, every lesson adds a milestone (m00 to m15) to the same project. Lessons 01–04 are scratch programs and apps that take no milestone.
  • Lesson anatomy. A lesson has a header with its estimate and milestone, a "why this matters" paragraph, concepts with diagrams, code excerpts (only the lines a section discusses), gotchas, retrieval checks, an unaided exercise, an agent brief, further reading, and the complete full files, collapsed at the end.
  • UI tracks. Lessons that touch UI have a switcher: Android XML | Compose | Both and iOS UIKit | SwiftUI | Both. Compose + SwiftUI is the default. XML and UIKit are there because the team's existing app still contains that code. An extra track adds time, shown in the estimate as +0.5 h for example.
  • Agent briefs. Every lesson from 01 on has a copy-paste brief near its end, just before further reading and the full files: where to start (the previous milestone, once there is one), the behaviour to build, the files involved and the acceptance checks. Hand it to your AI agent, or follow it yourself.
  • The never-blind code rule. You may let an agent write the code, but never blind. Read the lesson's code walkthrough, or have your agent explain its code line by line. Answer the retrieval checks. Then do the unaided exercise yourself. That last step isn't optional.

Before you start, check the environment requirements in the course plan.
