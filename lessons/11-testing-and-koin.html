Testing the App Core + Koin

~2.5 h · +0.25 h per extra UI track Milestone: m06 Koin wiring, green tests on JVM + iOS Prereq: 10
Why this matters: Lesson 10 promised that ports make the app core testable, and today you collect. A test drives the scanning service through its inbound port, DeviceScanning, exactly as the ViewModel does, with a fake radio behind the outbound port that the test controls. The same tests run on the JVM and on the iOS runtime, in milliseconds, with no device and no Bluetooth. Then you replace AppContainer with Koin, a DI container that runs on every KMP target. It binds each inbound port to its service and each outbound port to its adapter, so in Lesson 13 swapping in the real radios is one line. Koin checks those bindings only at run time, so one more test checks the whole graph. That's milestone m06.

1. Where a test plugs in

Lesson 10 named two kinds of inbound adapter: the shared ViewModels, and the tests. A test is just another caller of an inbound port. It calls DeviceScanning.scan(…) as the ViewModel does, so it tests what the app offers, not how the service is written inside. Behind the outbound port it plugs in a fake: an outbound adapter written for tests, which the test controls. Android's testing guide defines a fake as "A test double that has a "working" implementation of the class, but it is implemented in a way that makes it good for tests but unsuitable for production", and adds: "Fakes don't require a mocking framework and are lightweight. They are preferred." (Use test doubles). A test double is any object that stands in for a real one in a test.

  • App core
  • Inbound (port and adapter)
  • Outbound (port and adapter)
  1. The service test keeps the real ScanningService and replaces only the radio. It tests the app's rule, "each device once, names that contain the filter", which is the part you'd hate to break.
  2. The ViewModel test keeps the real ViewModel and replaces the whole app core with TestDeviceScanning, a test implementation of the inbound port. The course calls it that, not a fake: a fake stands in for the outside world behind an outbound port, and this one stands in for the inside. It means the ViewModel test fails only when the ViewModel is wrong, never because of the service's rule.
  3. No mocking library. Both doubles are ordinary classes that implement a port, a dozen lines each, written in commonTest, so they never ship in either app.

2. Set up commonTest

Tests in commonTest are written once and run on every target. Kotlin's docs: "For the android option, tests are run using JUnit 4", and for iosSimulatorArm64, the compiler "creates a test binary that is executed by Kotlin/Native's own test runner" (Test your multiplatform app). The shared build file gets one line and three test dependencies:

  1. withHostTest {} turns on Android's host (JVM) tests: "By default, the new plugin disables Android host-side (unit) and device-side (instrumented) tests" (Android-KMP plugin). See the gotcha below for what happens without it.
  2. kotlin("test") gives you @Test, @BeforeTest and assertEquals, mapped to JUnit on the JVM and to the Kotlin/Native runner on iOS.
  3. kotlinx-coroutines-test (the same version as coroutines) brings runTest, test dispatchers and virtual time. Turbine is "a small testing library for kotlinx.coroutines Flow" (Turbine). All three are commonTest dependencies, so they stay out of the apps.
Gotcha · green, but half the tests never ran We removed withHostTest {} and ran ./gradlew :shared:allTests. It printed BUILD SUCCESSFUL, and the only test task it ran was iosSimulatorArm64Test. The Android task didn't exist (task 'testAndroidHostTest' not found when asked for by name). The only hint was one line near the top of the output: WARNING: The 'commonTest' source directory exists, but android host tests are not enabled. A green build tells you that nothing failed, not that anything ran. Check the task list or the reports once, so you know both platforms really run.

3. The fake radio

The fake implements the outbound port, and the test plays the radio:

  1. hear(…) puts devices into a Channel, and the scan flow hands them to whoever collects, in order. UNLIMITED means trySend never waits and never drops, so a device heard before the collector is ready isn't lost.
  2. The flow never completes on its own, like a real radio's: emitAll keeps waiting for the next device until the collector cancels. That's the BleScanner contract from Lesson 10.
  3. failure makes the next scan throw. This is where m04's "fail" filter went: an error is something a radio does, so the fake radio does it on command.
  4. isScanning is true while a scan runs. The finally block runs when the collector cancels, so a test can check that cancelling a scan really stops the radio.
  5. It lives in package doubles under commonTest, next to TestDeviceScanning (section 5).

4. Test the service through its inbound port

The test builds the service with the fake, and from then on sees only the port:

  1. private val scanning: DeviceScanning: the declared type is the inbound port. The one line that names ScanningService builds it; every test after that is written against what the app offers. If you later split the service in two, the tests don't change.
  2. runTest runs a suspending test body on a test dispatcher with a virtual clock: it "will automatically skip any delays" (Testing coroutines).
  3. flow.test { … } (Turbine) collects the flow while the block runs. awaitItem() suspends until the next device arrives. Turbine applies "a wall clock time timeout that ignores runTest's virtual clock time", three seconds by default, so a device that never comes fails the test instead of hanging it.
  4. The end of the block checks what you didn't say. "When the validation block is complete, test cancels the coroutine and calls ensureAllEventsConsumed()". So if the service reported obd twice, the extra item would fail the test even though no line asks about it. Cancelling is also how the scan ends: the flow never completes, just like a real scan.
  5. Test names describe behaviour, so a failure reads like a broken rule: "reportsEachDeviceOnceAsSoonAsItIsHeard FAILED".

The other four tests each guard one promise from the port's comment:

  1. The filter test passes spaces and capitals. Only heart comes out, and Turbine's end-of-block check proves nothing else did.
  2. eachScanStartsWithNothingSeen runs two scans on the same service. It's Lesson 10's retrieval check turned into code: if seen were a property, the second scan would report nothing.
  3. An hour in no time. advanceTimeBy "Advances virtual time by the given amount and runs any coroutines scheduled to run before that point in virtual time". An hour of radio silence passes instantly, and the scan is still running: the service never stops a scan on its own. Then cancelling the collector runs the fake's finally, so the radio stops. That's "cancelling the collector stops it", proven.
  4. awaitError() suspends until the flow fails, and returns the exception. The radio's ScanException passes through the service unchanged, which is what the ViewModel's catch relies on.

5. Test the ViewModel against the inbound port

The ViewModel test needs something that implements DeviceScanning and does what the test says:

It looks like the fake radio, but it speaks the inbound port: whatever find(…) gets is already filtered and already unique, because that's what DeviceScanning promises. filters records each scan the ViewModel started and the filter it passed. Now the test:

  1. Dispatchers.setMain(StandardTestDispatcher()). viewModelScope runs on Dispatchers.Main, and on a local JVM "the Main dispatcher that wraps the Android UI thread will be unavailable". Android's rule: "The Main dispatcher should be replaced by a TestDispatcher in local unit tests" (Testing coroutines). resetMain() in @AfterTest puts it back.
  2. In @BeforeTest, not in a property. "If you create a TestDispatcher as a property of a test class, it won’t take its scheduler from the Main dispatcher, as the Main dispatcher is only replaced before each test method is executed."
  3. One clock for everything. "If the Main dispatcher has been replaced with a TestDispatcher, any newly-created TestDispatchers will automatically use the scheduler from the Main dispatcher, including the StandardTestDispatcher created by runTest". So the ViewModel's coroutine, its withTimeoutOrNull(3.seconds) and the test body share one virtual clock.
  4. @OptIn: setMain, resetMain and currentTime are marked experimental. Without the opt-in, each use prints a w: This declaration needs opt-in warning, which breaks the course's no-warnings rule. So the class opts in once, with a comment saying why.
  1. Read the first test as a story: idle; tap Scan; the app core finds obd (one row), then heart (two rows); then nothing, until the timeout turns Scanning into Finished.
  2. The timeout fires at once. When every coroutine is waiting, the scheduler moves the virtual clock straight to the next timer, the 3-second timeout. The last line proves it fired at exactly 3000 ms of virtual time. The diagram below shows the jump.
  3. testScheduler.runCurrent() "Runs coroutines that are scheduled at the current virtual time", without moving the clock. After the first startScan the scan job is running, so the second call must be ignored: filters holds only "obd". It also shows the ViewModel passes the filter on as typed. Trimming is the service's rule, tested in section 4.
  4. The error test is Lesson 08's "errors are state" rule: a failed scan becomes Idle plus a message, and errorShown() clears it. It uses skipItems(1) to skip states it isn't about.

6. What a DI container adds

AppContainer is fine for one screen. Android's Manual dependency injection page lists what goes wrong as the app grows: "You have to manage AppContainer yourself, creating instances for all dependencies by hand", "There is still a lot of boilerplate code", and you manage each container's scope and lifecycle yourself: "Doing this incorrectly can lead to subtle bugs and memory leaks in your app." A DI container does that bookkeeping: you declare once what each type is and how to build it, and the container works out the order. Android's own choice is Hilt, which is Android-only. Koin runs on every KMP target, so the shared code uses it. Koin has three kinds of definition that matter today:

DefinitionGives youOurs
single"One instance, kept for the lifetime of the Koin container"the BleScanner (one radio for the app) and the DeviceScanning service
factory"A new instance each time it is requested"none yet
viewModel"a new instance on each request, like a factory", kept by the platform's ViewModelStoreDeviceListViewModel

Quotes: Koin Definitions and ViewModel.

Injection, not lookup. Android contrasts DI with a service locator: "With the service locator pattern, classes have control and ask for objects to be injected; with dependency injection, the app has control and proactively injects the required objects." A lookup also hides what a class needs: "Dependencies are encoded in the class implementation, not in the API surface" (Dependency injection in Android). Koin can do both. KoinComponent with get() is a lookup, and Koin's docs say "Keep KoinComponent at the edges", for "a class that Koin does not create" (KoinComponent). The course's rule: constructors everywhere, lookups only at the platform edge. The app core, the ViewModels and the adapters never import Koin, and the tests in sections 4–5 never use it: they call constructors.

7. The Koin module, and where Koin starts

Add two Koin libraries to the shared code's commonMain, next to the m05 ones: implementation("io.insert-koin:koin-core:4.2.2"), the container and its DSL, and implementation("io.insert-koin:koin-core-viewmodel:4.2.2"), which adds viewModelOf for the multiplatform ViewModel. Then delete di/AppContainer.kt, and add the composition root as a Koin module:

  1. Read each line as a binding, as in AppContainer. single<BleScanner> { SimulatedBleScanner() }: "the outbound port BleScanner means this adapter, one for the app". Lesson 13 changes this line.
  2. single<DeviceScanning> { ScanningService(get()) }: "the inbound port means this service". get() asks Koin for whatever the constructor parameter needs, here a BleScanner. Because the type argument is the port, anyone can ask Koin for a DeviceScanning, but nobody can ask it for a ScanningService: the class stays hidden behind its port. One shared service is safe for the same reason as in Lesson 10: it keeps no state between scans.
  3. viewModelOf(::DeviceListViewModel) takes a constructor reference and fills each parameter with get(), here the DeviceScanning port. You no longer write the order: Koin works it out.
  4. internal val appModule. With a public module, the iOS header grew from 2,332 to 3,364 lines, 197 of them naming Koin_core… classes, because Kotlin exports every public type a public declaration mentions. Swift only needs to start Koin. internal keeps the module visible to tests in the same Gradle module and out of Swift's header. That's also why implementation is enough: no Koin type is in the shared code's public API.
  5. initKoin() is the one entry point both platforms call. Its signature has no Koin type in it. Koin can start only once per process: "A second call throws KoinApplicationAlreadyStartedException" (Starting Koin).
  • Inbound (port binding, ViewModel, test)
  • Outbound (port binding)
  • Android
  • iOS

Start Koin once, when the app starts. Koin must be running before the first screen asks for a ViewModel, and it must start exactly once, which rules out screens. Koin's docs: "Start Koin where your platform starts: the Application class on Android, the shared initKoin() function in a KMP project", and do it there "when code outside Compose (a Service, a WorkManager worker, iOS Swift code) also needs Koin" (Koin for Compose). Lesson 18's background worker will. Both Android tracks get a new class and one manifest attribute:

android:name tells the system which Application class to create. Leave it out, and the class compiles but never runs. We tried: the app crashed at launch with IllegalStateException: KoinApplication has not been started.

init() on the App runs once, before the first scene is built: SwiftUI's place for Application.onCreate. Without import Shared, which m05's file didn't need, Swift can't find AppModuleKt.

didFinishLaunchingWithOptions runs once per launch, before any scene connects, so Koin is up before SceneDelegate creates the first view controller (Lesson 04's app-level lifecycle).

Why doInitKoin? Top-level Kotlin functions become class methods on a class named after the file (AppModule.kt → AppModuleKt), as in Lesson 05. Objective-C treats names that start with init as initializers, so the Kotlin compiler adds a do prefix. You can see it in the generated header: + (void)doInitKoin __attribute__((swift_name("doInitKoin()")));.

8. Ask Koin for the ViewModel

Each screen asks Koin instead of AppContainer. The ViewModel store still keeps the ViewModel and still clears it; only the factory changes.

koinViewModel() does what viewModel(factory = …) did: it finds the nearest ViewModelStoreOwner, the navigation entry, and asks its store for the ViewModel, with a factory that asks Koin. The type comes from the parameter's declared type. In androidApp/build.gradle.kts, implementation("androidx.lifecycle:lifecycle-viewmodel-compose:2.11.0") is replaced by implementation("io.insert-koin:koin-compose-viewmodel:4.2.2"): the app no longer calls viewModel(…) itself, and Koin's library brings lifecycle-viewmodel-compose with it.

by viewModel() (singular, Koin's) replaces AndroidX's by viewModels { … } (plural): the same owner (this Fragment), the same lifetime, the same creation on first access; only the factory changes. Mind the one letter: the plural is AndroidX's, which falls back to the default factory. In androidApp/build.gradle.kts, add implementation("io.insert-koin:koin-android:4.2.2") at the end of dependencies { }. fragment-ktx is no longer used directly, but koin-android depends on it anyway, so the course keeps the explicit line.

iOS has no Koin integration with ViewModelStore, and doesn't need one: Lesson 08's resolver already takes any factory. Now it uses one that asks Koin, and Swift stops passing a factory at all:

  1. The factory parameter is gone. Swift no longer chooses how a ViewModel is built: it asks for a class, and the composition root decides.
  2. KoinViewModelFactory is a KoinComponent: a lookup, at the edge, in a class Koin doesn't create (section 6's rule). The store calls create only the first time it needs that ViewModel, so the store still owns its lifetime, and ViewModelOwner's deinit still clears it.
  3. Why our own four lines? Koin's docs cover ViewModels on Android and in Compose, not a Swift-side ViewModelStore. getKoin().get(modelClass) is Koin's public API, and the route through the store is Lesson 08's, unchanged.

In iosApp/iosApp/ViewModelOwner.swift (both iOS tracks), viewModel loses its parameter: func viewModel<VM: ViewModel>() -> VM calls store.resolveViewModel(modelClass: VM.self). Each screen's line gets shorter:

Swift infers VM from the declared type, the same trick as koinViewModel(). With AppContainer gone, Koin is imported in exactly three kinds of place: di/ (main and test), ViewModelResolver.kt, and on Android the one screen that asks for the ViewModel. Those are the edges.

9. Test the graph, because the compiler no longer does

Here is the price of a container. With AppContainer, a missing dependency was a compile error. With Koin, the module is a list of recipes read at run time. We deleted the single<BleScanner> line, and the Android app compiled without a warning, then crashed the moment the list screen appeared:

FATAL EXCEPTION: main
…
Caused by: …InstanceCreationException: Could not create instance for '[Factory: '…adapter.inbound.DeviceListViewModel']'
Caused by: …InstanceCreationException: Could not create instance for '[Singleton: '…core.inbound.DeviceScanning']'
Caused by: …NoDefinitionFoundException: No definition found for type '…core.outbound.BleScanner' on scope '['_root_']'.

Read the chain from the bottom up: the missing piece, then each thing that needed it. Notice that Koin names the binding by its port, DeviceScanning, not by the service. One test asks for every ViewModel, so this failure shows up in allTests instead of on a phone:

  1. koinApplication { … } "creates a container that is not registered in GlobalContext" (Starting Koin), unlike startKoin. Tests don't leak into each other, and the once-per-process rule doesn't bite.
  2. It sees appModule because internal means "the same Gradle module", and commonTest is compiled with commonMain's module.
  3. Building the ViewModel is safe without setMain: nothing touches viewModelScope until startScan.
  4. Keep it current. Every new screen adds one get<…ViewModel>() line here. With the binding deleted, this test fails with the same three-line chain as the crash, on the JVM and on iOS.

The other eight tests don't use Koin: they call constructors with test doubles. That's the point of constructor injection: the container is for the app, not for the tests.

10. What actually happens

We built m06 on all four tracks (Kotlin 2.4.20, Koin 4.2.2, coroutines 1.11.0, Turbine 1.2.1, AGP 9.4.1, Xcode 26.2). allTests passed 9 of 9 tests on the JVM and 9 of 9 on the iOS simulator. Both apps look and behave as m05: five rows about 0.3 s apart, "Devices found: 5" at 3 s, sens finds one row. The builds print no compiler warnings from our code, and the iOS header contains no Koin types.

m06 is a natural stop. It's done when allTests runs both test tasks green, and both apps build and behave as m05. Commit it before the next lesson, which adds the first new capability through both port kinds: permissions.

Retrieval checks

Answer from memory, without scrolling up.

Why does ScanningServiceTest declare scanning as DeviceScanning rather than ScanningService?

The test checks what the app offers, through the same port the ViewModel uses, so it survives any rewrite of the service's insides. Koin plays no part in the service tests.

The ViewModel test waits for a 3-second timeout. Why does it take a few milliseconds?

Main is a test dispatcher, and runTest shares its scheduler. When every coroutine is waiting, the scheduler moves the clock to the next timer, the timeout at 3000 ms. Turbine's own timeout counts wall-clock time.

Why does the ViewModel test use TestDeviceScanning and not the real service with FakeBleScanner?

The ViewModel depends only on the inbound port, so its test replaces everything behind that port. The scan rule has its own tests in ScanningServiceTest.

You delete a binding from appModule. When do you find out?

Koin resolves at run time. That's why AppModuleTest exists: it moves the failure from the phone into allTests.

Why is appModule declared internal?

A public Module drags Koin's classes into the exported header (about a thousand extra lines). Tests in the same Gradle module still see internal declarations.

Mixed review (interleaved)

Koin now builds the ViewModel. On iOS, what still clears it? (Lesson 08)

A viewModel definition creates a new instance per request. Keeping and clearing it is the store's job, and on iOS the owner's deinit calls store.clear().

Lesson 13 swaps SimulatedBleScanner for the real radios. Which file changes for the wiring? (Lesson 10)

Which adapter implements BleScanner is a wiring decision, made only in the composition root. The service, the ViewModel and the screens know only ports.

package com.example.devicemonitor

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.ViewModelStore
import androidx.lifecycle.viewmodel.CreationExtras
import kotlinx.cinterop.BetaInteropApi
import kotlinx.cinterop.ObjCClass
import kotlinx.cinterop.getOriginalKotlinClass
import org.koin.core.component.KoinComponent
import kotlin.reflect.KClass

// Swift can't pass a KClass, only its Objective-C class. This turns it back into the
// KClass that ViewModelProvider needs. Adapted from Android's KMP ViewModel guide.
@OptIn(BetaInteropApi::class)
@Throws(IllegalArgumentException::class)
fun ViewModelStore.resolveViewModel(modelClass: ObjCClass): ViewModel {
    @Suppress("UNCHECKED_CAST")
    val vmClass = getOriginalKotlinClass(modelClass) as? KClass<ViewModel>
    require(vmClass != null) { "The modelClass parameter must be a ViewModel type." }
    return ViewModelProvider.create(this, KoinViewModelFactory)[vmClass]
}

// The store calls this the first time it needs a ViewModel; Koin builds it from appModule.
private object KoinViewModelFactory : ViewModelProvider.Factory, KoinComponent {
    override fun <T : ViewModel> create(modelClass: KClass<T>, extras: CreationExtras): T =
        getKoin().get(modelClass)
}

import com.example.devicemonitor.core.Device

import kotlinx.coroutines.flow.flow
import kotlinx.coroutines.flow.receiveAsFlow

// Fake: an outbound adapter written for tests, behind the BleScanner port. The test plays
// the radio: it decides what is heard and when, and whether the radio fails.
class FakeBleScanner : BleScanner {
    private val heard = Channel<Device>(Channel.UNLIMITED)
    var failure: ScanException? = null
    var isScanning = false
        private set

    override fun scan(): Flow<Device> = flow {
        failure?.let { throw it }
        isScanning = true
        try {
            emitAll(heard.receiveAsFlow())
        } finally {
            isScanning = false
        }
    }

    fun hear(vararg devices: Device) {
        devices.forEach { heard.trySend(it) }
    }
}

// Stateful: owns the filter text and connects the shared ViewModel to the content below.
@Composable
fun DeviceListScreen(
    onDeviceClick: (Device) -> Unit,
    viewModel: DeviceListViewModel = koinViewModel(),
) {
    var filter by rememberSaveable { mutableStateOf("") }
    val state by viewModel.uiState.collectAsStateWithLifecycle()

    DeviceListContent(
        filter = filter,
        onFilterChange = { filter = it },
        isScanning = state.scan is ScanState.Scanning,
        devices = when (val scan = state.scan) {
            ScanState.Idle -> null
            is ScanState.Scanning -> scan.found
            is ScanState.Finished -> scan.found
        },
        onScan = { viewModel.startScan(filter) },
        onDeviceClick = onDeviceClick,
    )

    state.errorMessage?.let { message ->
        AlertDialog(
            onDismissRequest = viewModel::errorShown,
            confirmButton = { TextButton(onClick = viewModel::errorShown) { Text("OK") } },
            title = { Text("Scan failed") },
            text = { Text(message) },
        )
    }
}

@Composable
fun DeviceListContent(

    isScanning: Boolean,

    onScan: () -> Unit,
    onDeviceClick: (Device) -> Unit,
) {

import kotlinx.coroutines.launch
import org.koin.androidx.viewmodel.ext.android.viewModel

class DeviceListFragment : Fragment() {
    // Survives rotation and the trip to the detail screen; cleared when this
    // Fragment leaves the back stack for good.
    private val viewModel: DeviceListViewModel by viewModel()

    private var binding: FragmentDeviceListBinding? = null
    private var errorDialog: AlertDialog? = null
    private val adapter = DeviceAdapter { device ->
        val nav = findNavController()
        // A fast double tap delivers two clicks; only navigate from the list itself.
        if (nav.currentDestination?.id == R.id.deviceList) {
            nav.navigate(R.id.toDetail, Bundle().apply { putString("deviceId", device.id) })
        }
    }

    override fun onCreateView(inflater: LayoutInflater, container: ViewGroup?, savedInstanceState: Bundle?): View {
        val b = FragmentDeviceListBinding.inflate(inflater, container, false)
        binding = b
        b.deviceList.adapter = adapter
        b.deviceList.addItemDecoration(DividerItemDecoration(requireContext(), DividerItemDecoration.VERTICAL))
        b.scanButton.setOnClickListener { viewModel.startScan(b.filterInput.text.toString()) }
        return b.root
    }

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        viewLifecycleOwner.lifecycleScope.launch {
            viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.uiState.collect { render(it) }
            }
        }
    }

    override fun onDestroyView() {
        super.onDestroyView()
        errorDialog?.dismiss() // a dismiss() doesn't call the cancel listener, so the error stays in state
        errorDialog = null
        binding?.deviceList?.adapter = null // the adapter outlives the view; don't let it keep the old list
        binding = null
    }

    // The one place that touches views: every new state ends here. The EditText keeps its
    // own text (and restores it after rotation), so render() never sets it.
    private fun render(state: DeviceListUiState) {
        val b = binding ?: return
        val isScanning = state.scan is ScanState.Scanning
        val devices = when (val scan = state.scan) {
            ScanState.Idle -> null
            is ScanState.Scanning -> scan.found
            is ScanState.Finished -> scan.found
        }
        b.scanButton.isEnabled = !isScanning
        b.progress.visibility = if (isScanning) View.VISIBLE else View.GONE
        b.statusText.text = when {
            isScanning -> "Scanning…"
            devices == null -> "Tap Scan to look for devices."
            devices.isEmpty() -> "No devices found. Try another filter."
            else -> "Devices found: ${devices.size}"
        }
        b.statusText.setTextColor(if (devices?.isEmpty() == true && !isScanning) Color.RED else Color.DKGRAY)
        adapter.submitList(devices.orEmpty())
        renderError(state.errorMessage)
    }

    private fun renderError(message: String?) {
        if (message == null) {
            errorDialog?.dismiss()
            errorDialog = null
        } else if (errorDialog == null) {
            errorDialog = AlertDialog.Builder(requireContext())
                .setTitle("Scan failed")
                .setMessage(message)
                .setPositiveButton("OK") { _, _ -> viewModel.errorShown() }
                .setOnCancelListener { viewModel.errorShown() }
                .show()
        }
    }
}

import Shared

// iOS has no ViewModelStoreOwner, so this class plays that role. Keep it in a view's
// @State (or a view controller's property). When it is deinitialised, clearing the store
// cancels every viewModelScope in it and calls onCleared().
final class ViewModelOwner {
    private let store = ViewModelStore()

    // Returns the store's instance of VM; Koin creates it on first use.
    func viewModel<VM: ViewModel>() -> VM {
        do {
            return try store.resolveViewModel(modelClass: VM.self) as! VM
        } catch {
            fatalError("Couldn't create \(VM.self): \(error)")
        }
    }

    deinit {
        store.clear()
    }
}

import SwiftUI
import Shared

// Stateful: owns the filter text and connects the shared ViewModel to the content below.
struct DeviceListView: View {
    @State private var owner = ViewModelOwner()
    @State private var filter = ""
    @State private var state: DeviceListUiState?

    var body: some View {
        let viewModel: DeviceListViewModel = owner.viewModel()
        let state = self.state ?? viewModel.uiState.value
        DeviceListContent(
            filter: $filter,
            isScanning: state.scan is ScanStateScanning,
            devices: devices(in: state.scan),
            onScan: { viewModel.startScan(filter: filter) }
        )
        .alert(
            "Scan failed",
            isPresented: Binding(
                get: { state.errorMessage != nil },
                set: { if !$0 { viewModel.errorShown() } }
            ),
            actions: { Button("OK") {} },
            message: { Text(state.errorMessage ?? "") }
        )
        .task {
            for await newState in viewModel.uiState {
                self.state = newState
            }
        }
    }

    // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
    private func devices(in scan: ScanState) -> [Device]? {
        switch onEnum(of: scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
    }
}

// Stateless: renders whatever it's given, reports events up.
struct DeviceListContent: View {
    @Binding var filter: String
    let isScanning: Bool
    let devices: [Device]?
    let onScan: () -> Void

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            TextField("Device name filter", text: $filter)
                .textFieldStyle(.roundedBorder)
                .autocorrectionDisabled()
            Button(action: onScan) {
                Text("Scan")
                    .frame(maxWidth: .infinity)
            }
            .buttonStyle(.borderedProminent)
            .disabled(isScanning)
            ScanStatus(isScanning: isScanning, devices: devices)
            List(devices ?? [], id: \.id) { device in
                NavigationLink(value: DeviceRoute(id: device.id)) {
                    DeviceRow(device: device)
                }
            }
            .listStyle(.plain)
        }
        .padding()
        .navigationTitle("Device Monitor")
    }
}

private struct ScanStatus: View {
    let isScanning: Bool
    let devices: [Device]?

    var body: some View {
        if isScanning {
            HStack {
                ProgressView()
                Text("Scanning…")
            }
        } else if let devices {
            if devices.isEmpty {
                Text("No devices found. Try another filter.")
                    .foregroundStyle(.red)
            } else {
                Text("Devices found: \(devices.count)")
            }
        } else {
            Text("Tap Scan to look for devices.")
        }
    }
}

private struct DeviceRow: View {
    let device: Device

    var body: some View {
        HStack {
            VStack(alignment: .leading) {

                    .font(.caption)
                    .foregroundStyle(.secondary)
            }

                .font(.caption)
        }
    }
}

import UIKit
import Shared

final class DeviceListViewController: UIViewController, UITableViewDelegate {
    private let owner = ViewModelOwner()
    private lazy var viewModel: DeviceListViewModel = owner.viewModel()
    private var observation: Task<Void, Never>?

    private let filterField = UITextField()
    private let scanButton = UIButton(configuration: .filled())
    private let spinner = UIActivityIndicatorView(style: .medium)
    private let statusLabel = UILabel()
    private let tableView = UITableView()
    private lazy var dataSource = UITableViewDiffableDataSource<Int, String>(tableView: tableView) {
        tableView, indexPath, deviceId in
        let cell = tableView.dequeueReusableCell(withIdentifier: "device", for: indexPath)
        var content = UIListContentConfiguration.subtitleCell()
        if let device = SampleDevices.shared.find(id: deviceId) {
            content.text = device.name
            content.secondaryText = "\(device.id)   \(device.rssi) dBm"
        }
        cell.contentConfiguration = content
        cell.accessoryType = .disclosureIndicator
        return cell
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        title = "Device Monitor"
        navigationController?.navigationBar.prefersLargeTitles = true
        view.backgroundColor = .systemBackground

        filterField.placeholder = "Device name filter"
        filterField.borderStyle = .roundedRect
        filterField.autocorrectionType = .no
        scanButton.configuration?.title = "Scan"
        scanButton.addAction(UIAction { [weak self] _ in
            guard let self else { return }
            viewModel.startScan(filter: filterField.text ?? "")
        }, for: .touchUpInside)
        statusLabel.numberOfLines = 0
        tableView.register(UITableViewCell.self, forCellReuseIdentifier: "device")
        tableView.delegate = self

        let statusRow = UIStackView(arrangedSubviews: [spinner, statusLabel])
        statusRow.spacing = 8
        let stack = UIStackView(arrangedSubviews: [filterField, scanButton, statusRow, tableView])
        stack.axis = .vertical
        stack.spacing = 12
        stack.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(stack)
        NSLayoutConstraint.activate([
            stack.topAnchor.constraint(equalTo: view.layoutMarginsGuide.topAnchor),
            stack.leadingAnchor.constraint(equalTo: view.layoutMarginsGuide.leadingAnchor),
            stack.trailingAnchor.constraint(equalTo: view.layoutMarginsGuide.trailingAnchor),
            stack.bottomAnchor.constraint(equalTo: view.bottomAnchor),
        ])
        render(viewModel.uiState.value)
    }

    // Collect only while on screen, like repeatOnLifecycle(STARTED) on Android.
    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        observation?.cancel()
        observation = Task {
            for await state in viewModel.uiState {
                render(state)
            }
        }
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        observation?.cancel()
        observation = nil
    }

    // The one place that touches views: every new state ends here. The text field owns
    // its own text, so render() never sets it.
    private func render(_ state: DeviceListUiState) {
        let isScanning = state.scan is ScanStateScanning
        // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
        let devices: [Device]? = switch onEnum(of: state.scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
        scanButton.isEnabled = !isScanning
        if isScanning { spinner.startAnimating() } else { spinner.stopAnimating() }
        spinner.isHidden = !isScanning
        if isScanning {
            statusLabel.text = "Scanning…"
        } else if let devices {
            statusLabel.text = devices.isEmpty
                ? "No devices found. Try another filter."
                : "Devices found: \(devices.count)"
        } else {
            statusLabel.text = "Tap Scan to look for devices."
        }
        statusLabel.textColor = devices?.isEmpty == true && !isScanning ? .systemRed : .label

        var snapshot = NSDiffableDataSourceSnapshot<Int, String>()
        snapshot.appendSections([0])
        snapshot.appendItems((devices ?? []).map(\.id))
        dataSource.apply(snapshot, animatingDifferences: true)
        renderError(state.errorMessage)
    }

    private func renderError(_ message: String?) {
        guard let message, presentedViewController == nil else { return }
        let alert = UIAlertController(title: "Scan failed", message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "OK", style: .default) { [weak self] _ in
            self?.viewModel.errorShown()
        })
        present(alert, animated: true)
    }

    func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        tableView.deselectRow(at: indexPath, animated: true)
        guard let deviceId = dataSource.itemIdentifier(for: indexPath) else { return }
        navigationController?.pushViewController(DeviceDetailViewController(deviceId: deviceId), animated: true)
    }
}
