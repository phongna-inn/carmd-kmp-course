API client with Ktor

~2.5 h · +0.5 h per extra UI track Milestone: e1 API screen: success / error / timeout Prereq: 20 (m15)
Why this matters: almost every app the team ships talks to a server, and the network is where an app fails most often: no signal, a host that doesn't answer, a 404, a server that takes forever. The Native Device Monitor has no server, so this extension gives it a place to try one: an API test screen with a URL field, GET and POST, and the answer or the error shown (the course plan's Appendix A.5). The point isn't the screen. It's where the HTTP code goes: in one outbound adapter in the shared code, over Ktor, behind a port named for what the app needs. Nothing else in the app knows which HTTP library it uses, and the tests run without a network. That gives milestone e1: success, error and timeout, on both platforms.

Primary source Ktor's client docs: Client engines before section 3, Content negotiation and serialization before section 4, Timeout and Response validation before section 5, and Testing before section 9. For section 8: Android's Network security configuration and Apple's Preventing insecure network connections.

Tracks The ports, the service, the Ktor adapter, the ViewModel and every test are shared code, the same on every track. The engines live in androidMain and iosMain, so both tracks of a platform share them. The tracks differ in the API test screen and in the button that opens it (section 7); the extra 0.5 h per track is those two on XML or UIKit. 1. A port named for what the app needs

The first idea most people have is an ApiClient interface in the app core with get and post on it. The course plan says no (ADR 0001): an outbound port is named in the app's terms, never HTTP's. An ApiClient port would put the transport in the middle of the app, and every feature that needs a server would depend on the same wide interface. Instead, each need gets its own port. A real feature would get one named for its job, a LogUploader for the monitor's records, say, and the core would never hear about URLs. The test screen's job is different: trying an endpoint by hand. So its port is EndpointProbe, and it does talk about URLs, because a URL is what that screen is about.

  1. Only the app's own types. Strings, maps, a Duration, ProbeMessage and ProbeResult, all in the app core. No HttpResponse, no HttpStatusCode, no Ktor exception. The refactor checklist's grep (Lesson 20) still finds no io.ktor import under core/.
  2. "Never throws" is part of the port. A network fails often and in many ways; each way is a value the service can reason about. The adapter's job is to turn every failure it can meet into one of three results (section 5), so no Ktor or platform exception reaches the core.
  3. The time limit is an argument. How long the screen waits is a rule of the app, and rules live in the service, as the scan's 10 s did in Lesson 20. The adapter only enforces the number it's given.
  4. POST sends a ProbeMessage, not JSON. The core says what to send (a greeting and when it was sent); the adapter decides it goes as JSON. That's the same split as Lesson 17's log store, whose records know nothing about JSON Lines.

2. The service: the screen's rules

The inbound port is what the screen's ViewModel calls: get(url, params) and post(url), each returning an ApiTestResult, never throwing. The service decides what to send and what the answer means:

  1. A text that isn't a web URL is never sent. "example.com" or "ftp://…" becomes InvalidUrl before the port is called, and the screen says what to type. The check is deliberately small: a scheme, a host, no spaces. Anything subtler is the adapter's to catch (section 5).
  2. 2xx is success; any other status is an HTTP error. That's a rule of the app, so it's here, not in Ktor's settings. The server did answer, so the body still goes to the screen: a 404 page often says why.
  3. A timeout says how long the screen waited. TimedOut(TIME_LIMIT) carries the service's own number, so the words on screen ("no answer within 10 s") can't drift from the limit the adapter was given.
  4. The clock is a constructor parameter, Clock.System by default, as in MonitoringService: a test pins sentAt to a known instant.

ApiTestResult has five cases: Success, HttpError, TimedOut, Unreachable and InvalidUrl. It's what A.5 means by "its service turns timeouts and network errors into results the UI can show": typed results, which the ViewModel puts into words (section 6).

3. Ktor inside one adapter

Ktor is JetBrains' Kotlin framework for HTTP servers and clients, and its client is Kotlin Multiplatform. The client's API is the same on every platform; what actually opens sockets is an engine, and each platform has its own. The shared module gets Ktor's core, its JSON plugin and its JSON format in commonMain, one engine per platform, and the mock engine for tests:

The kotlinx.serialization plugin, which Ktor's JSON needs, is already in the shared module since Lesson 17. The adapter takes its engine from outside, the pattern Ktor's testing guide shows (its ApiClient(engine) gets CIO.create() in the app and a MockEngine in the test):

  1. The engine is a parameter. In the app it's the platform's; in the tests it's a MockEngine that answers without a network (section 9). Everything else, the plugins included, is the same code in both.
  2. Per-platform engines, with expect/actual. Lesson 05's mechanism, back for a real reason: commonMain declares that an engine exists, and each platform's source set says which. OkHttp is the engine Ktor's Android example uses; Darwin "uses NSURLSession under the hood". Ktor's docs also offer ktor-client-engine-defaults, one artifact that picks an engine per target for you; the course spells the engines out so you can see them.
  3. internal. The adapter and httpEngine() are visible inside the shared module only. Koin builds the adapter in shared code (section 6), and Swift has no reason to see a Ktor type, so none reaches the framework's header.
  4. Nothing outside these four files imports Ktor: KtorEndpointProbe.kt and the three HttpEngine files. That's A.5's "Nothing outside that adapter imports Ktor", with the engine function counted as part of the adapter. The agent brief checks it with a grep.

4. GET, POST and JSON

  1. Parameters go through parameter(), not string concatenation. Ktor encodes them: the adapter test sends name = "OBD II" and the URL becomes ?name=OBD+II&max=5. Gluing "?name=$name" onto a URL breaks on the first space or &.
  2. A per-request timeout. install(HttpTimeout) once, then timeout { … } on each request: "timeouts specified for a specific request override global timeouts from the install block" (Ktor's Timeout page). The request timeout is the whole call, "from sending a request to receiving a response".
  3. JSON out: a @Serializable class and a content type. setBody hands the object to ContentNegotiation, which serializes it for the content type you set. The class lives in the adapter, so the core's ProbeMessage carries no annotation; sentAt goes as the ISO text Instant.toString() prints, as in Lesson 17's log.
  4. The service's Accept header arrives once. ContentNegotiation adds Accept: application/json by itself when a request doesn't have it. Our first adapter test, with and without the service's header, saw exactly one application/json both times, and httpbin echoed one. The service still sets it: the rule "ask for JSON" belongs to the app, not to a plugin we might swap.
  1. JSON in: body<T>(). A screen that takes any URL can't know the answer's shape, so T is JsonElement, kotlinx.serialization's "any JSON" type. A real feature would ask for its own @Serializable class here, still inside its adapter.
  2. Indented for people. Re-encoding with prettyPrint turns {"id":1,"done":false} into one field per line, which is what the screen shows. Any other content type comes as the server sent it.
  3. A server that says JSON and sends something else makes body<JsonElement>() throw a ContentConvertException (Ktor's JsonConvertException extends it). The adapter shows the raw text instead: the answer is still an answer. Reading the body a second time works because a response from client.get or client.post is read into memory before it's returned to you.

5. What can go wrong: status, timeouts, network errors

Every request ends in one of a handful of ways. The adapter, the service and the ViewModel each turn them one step further, from what Ktor reports into what a person reads:

  1. A status is never an exception here. Ktor's client "does not validate responses based on their HTTP status codes" unless you set expectSuccess = true, which would throw ClientRequestException for 4xx and ServerResponseException for 5xx. The adapter leaves it off: judging a status is the service's rule (section 2), and a 404 should reach it as an answer.
  2. Three timeouts, one result. Ktor has a request timeout (the whole call), a connect timeout and a socket timeout ("a maximum time of inactivity between two data packets"), each with its own exception. For the screen they all mean "no answer in time". Not every engine has all three: Ktor's table says Darwin supports the request and socket timeouts but not the connect timeout. That's one reason the adapter sets the request timeout, which every engine we use honours.
  3. The order of the catches matters. All three timeout exceptions are IOExceptions too, on Android and on iOS. Kotlin tries the catch clauses top to bottom, so with IOException first, a timeout would show as "couldn't reach the server".
  4. IOException is the network's catch-all. It's kotlinx.io.IOException, which on Android is java.io.IOException itself. OkHttp's "Unable to resolve host" and Darwin's NSURLErrorDomain errors both arrived as one (section 10 shows what each said).
  5. A URL can fail before anything is sent, and not with an IOException. "https://example.com:99999/" passes the service's check, and Ktor's own parser throws URLParserException, "Fail to parse url". The engines are stricter still, each in its own way: for "https://[::1/" OkHttp throws IllegalArgumentException ("Invalid URL host"), and Darwin throws IllegalStateException ("Invalid url") for "https://a<b.com/" and even a NullPointerException for "https://[::1/". None of those is a network error, but each one escapes a catch for IOException, and an exception that escapes the adapter goes up through the ViewModel's coroutine: our first adapter caught only the IO and parser failures, and a GET on "https://[::1/" crashed the app on the Android emulator. So the last clause catches every other Exception, and the screen says "couldn't reach the server" with the exception's message.
  6. Except a cancellation, which passes through on purpose. Leaving the screen cancels the request with a CancellationException, which must reach the coroutine machinery (Lesson 08). It is an Exception too, so the clause just before the catch-all rethrows it; without that, the catch-all would turn a cancelled request into Unreachable and the cancelled coroutine would carry on. Kotlin's Cancellation and timeouts guide: "If you must catch it, rethrow it". Lesson 08's rule, catch only what you can handle, still holds: here the adapter can handle every failure, since each one becomes a result.

6. Koin and the ViewModel

The platform module and initKoin's nine parameters don't change: an adapter written in Kotlin in commonMain needs nothing from an app start, like Lesson 17's SessionConnectionStatus. Swapping the probe for another one is still one line.

  1. The words are the ViewModel's. The service says what happened, as types; the inbound adapter says it to a person, as Lesson 20's StatusText does. A second screen could word the same results differently without touching the core.
  2. The newest request wins. GET and POST are disabled while one is on its way, but the ViewModel doesn't rely on the screen: it cancels the earlier request, so an old answer can never land after a newer one (the same rule as the monitor's log reads in Lesson 20).
  3. Cancelling a request is free. viewModelScope is cancelled when the ViewModel is cleared (Lesson 08), and Ktor's calls are suspending functions that stop when their coroutine is cancelled. Leave the screen in the middle of a 10-second wait and the request ends with it. Our runs did exactly that on all four tracks, with no crash and no late update.
  4. A long body is shortened to its first 4,000 characters, with "… and N more characters": a web page can be megabytes, and a text view isn't a browser. The URL field starts with SUGGESTED_URL, https://httpbin.org/anything, an echo service that answers GET and POST with JSON describing the request it received.

8. The platforms' own rules

The shared code is the same on both platforms; what each platform lets an app send isn't.

  1. Plain http:// is blocked on both, by default. On Android, "starting with Android 9 (API level 28), cleartext support is disabled by default": our GET on http://httpbin.org/get came back as "couldn't reach the server" with OkHttp's "CLEARTEXT communication to httpbin.org not permitted by network security policy". On iOS, App Transport Security asks apps to "use secure URLs, like those beginning with https", and "otherwise, ATS denies the connection": Darwin reported NSURLErrorDomain Code=-1022, "the App Transport Security policy requires the use of a secure connection". Both arrive as an IOException, so the screen shows them as it shows any unreachable server. Each platform lets you allow cleartext for named domains (a network security config, ATS exceptions in Info.plist); the API screen doesn't, and a real app rarely should.
  2. The INTERNET permission. Android apps need it to open sockets; it's an install-time permission, granted without a prompt. In this build OkHttp's own library manifest declares it, and the manifest merger adds it to the app (the merged manifest says "ADDED from [com.squareup.okhttp3:okhttp-android:5.5.0]"), so the app worked before we added the line. The app declares it anyway: what an app uses belongs in its own manifest, not in whichever engine it happens to depend on today. iOS has no such permission for HTTPS.
  3. A keyboard made for URLs. KeyboardType.Uri, textUri and .URL put / and . on the letters page (the emulator's Gboard shows both next to the space bar; Apple's .URL keyboard also features ".com"), and the iOS fields turn off autocapitalization, so "https" doesn't become "Https".
Gotcha · autocorrect in a URL field Autocorrect works on words, and a URL isn't one: a keyboard that "corrects" a host or a path changes the request, and a check like the cleartext one above can then pass for the wrong reason. Compose leaves autocorrect to the keyboard unless you say otherwise (autoCorrectEnabled defaults to null, "soft keyboard default configurations should apply", and it applies to KeyboardType.Uri), so the field sets autoCorrectEnabled = false. On our emulator, typing through adb kept http://httpbin.org/get as typed with or without that line, while Gboard still offered word suggestions without it; agent brief check 7 still reads the field before it trusts the cleartext result. The XML textUri input type has no autocorrect flag (textAutoCorrect is a separate one, and "without this flag, the IME will not try to correct typos"), and the iOS tracks use .autocorrectionDisabled() and .autocorrectionType = .no.
Gotcha · the platform's own words Unreachable(reason) carries the exception's message, and the two engines word things very differently. OkHttp on the emulator: "Unable to resolve host "no-such-host.invalid": No address associated with hostname". Darwin on the Simulator: "Exception in http request: Error Domain=NSURLErrorDomain Code=-1003 "A server with the specified hostname could not be found." UserInfo={…}", several lines of it. That's fine for a test screen, whose user is a developer. A real feature would name its failures in the app's terms (offline, host not found, refused) and word them in its ViewModel, the way ProbeResult already does for timeouts.

Why does the app core get an EndpointProbe port instead of an ApiClient port with get and post?

ADR 0001: "ApiClient in Extension E1 stops being a port." The test screen's need happens to be "try a URL", so its port talks about URLs.

The server answers 404. What does KtorEndpointProbe return, and who decides that it's an error?

With expectSuccess off (Ktor's default), a status is an answer. Judging it is a rule of the app, so it lives in the service.

Why do the three timeout catch clauses come before catch (e: IOException)?

Clauses are tried top to bottom. Kotlin, unlike Java, doesn't reject a broader clause placed before a narrower one; it just never reaches the narrower one.

The user taps GET on a server that never answers, then goes Back after one second. What happens to the request?

That's why the adapter rethrows a CancellationException before its last clause, catch (e: Exception): a cancellation must pass through, and only real failures become Unreachable.

        message: ProbeMessage,
        headers: Map<String, String>,

package com.example.devicemonitor.core

// What one request to an endpoint came back with, in the app's terms: no HTTP library's types.
// The EndpointProbe adapters return it and never throw.
sealed interface ProbeResult {
    // The server answered, with any status: 200, 404 and 500 are all answers. The body is text;
    // a JSON body comes indented, ready to show.
    data class Answered(val status: Int, val body: String) : ProbeResult

    // No full answer within the time limit.
    data object TimedOut : ProbeResult

    // No answer at all: no network, a host that doesn't exist, a refused or broken connection,
    // or a request the platform won't send. The reason is the platform's own words.
    data class Unreachable(val reason: String) : ProbeResult
}

package com.example.devicemonitor.core

import com.example.devicemonitor.core.inbound.ApiTesting
import com.example.devicemonitor.core.outbound.EndpointProbe
import kotlin.time.Clock
import kotlin.time.Duration.Companion.seconds

// Service: the API test screen's rules. Only http:// and https:// URLs are sent; every request
// asks for JSON and gets the same time limit; a 2xx status is a success and any other an HTTP
// error; and a timeout or a missing network becomes a result the screen can show.
class ApiTestingService(
    private val probe: EndpointProbe,
    private val clock: Clock = Clock.System,
) : ApiTesting {
    override suspend fun get(url: String, params: Map<String, String>): ApiTestResult {
        val target = url.trim()
        if (!isWebUrl(target)) return ApiTestResult.InvalidUrl(target)
        return judge(probe.get(target, params, ASK_FOR_JSON, TIME_LIMIT))
    }

    override suspend fun post(url: String): ApiTestResult {
        val target = url.trim()
        if (!isWebUrl(target)) return ApiTestResult.InvalidUrl(target)
        val message = ProbeMessage(GREETING, clock.now())
        return judge(probe.post(target, message, ASK_FOR_JSON, TIME_LIMIT))
    }

    private fun judge(result: ProbeResult): ApiTestResult = when (result) {
        is ProbeResult.Answered ->
            if (result.status in 200..299) ApiTestResult.Success(result.status, result.body)
            else ApiTestResult.HttpError(result.status, result.body)
        ProbeResult.TimedOut -> ApiTestResult.TimedOut(TIME_LIMIT)
        is ProbeResult.Unreachable -> ApiTestResult.Unreachable(result.reason)
    }

    // "https://host…" or "http://host…", with a host and no spaces. The adapter checks the rest.
    private fun isWebUrl(url: String): Boolean {
        val rest = when {
            url.startsWith("https://", ignoreCase = true) -> url.substring(8)
            url.startsWith("http://", ignoreCase = true) -> url.substring(7)
            else -> return false
        }
        val host = rest.substringBefore('/').substringBefore('?').substringBefore('#')
        return host.isNotEmpty() && url.none { it.isWhitespace() }
    }

    companion object {
        // How long the screen waits for a whole answer before it says "no answer".
        val TIME_LIMIT = 10.seconds
        const val GREETING = "Hello from the Native Device Monitor"
        private val ASK_FOR_JSON = mapOf("Accept" to "application/json")
    }
}

import com.example.devicemonitor.core.ProbeMessage
import com.example.devicemonitor.core.ProbeResult

import io.ktor.client.network.sockets.ConnectTimeoutException
import io.ktor.client.network.sockets.SocketTimeoutException
import io.ktor.client.plugins.HttpRequestTimeoutException
import io.ktor.client.plugins.HttpTimeout
import io.ktor.client.plugins.contentnegotiation.ContentNegotiation
import io.ktor.client.plugins.timeout
import io.ktor.client.request.get
import io.ktor.client.request.header
import io.ktor.client.request.parameter
import io.ktor.client.request.post

import io.ktor.client.statement.bodyAsText

import io.ktor.serialization.kotlinx.json.json
import kotlinx.io.IOException
import kotlinx.serialization.Serializable
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonElement
import kotlin.coroutines.cancellation.CancellationException
import kotlin.time.Duration

// Outbound adapter: the EndpointProbe port over Ktor, shared by both platforms. With its engine
// function (HttpEngine.kt), the only code in the app that imports Ktor. The engine comes from
// outside: the platform's (httpEngine()) in the app, a MockEngine in the tests.
internal class KtorEndpointProbe(engine: HttpClientEngine) : EndpointProbe {
    private val client = HttpClient(engine) {
        // JSON both ways: setBody(@Serializable object) sends it, body<T>() reads it.
        install(ContentNegotiation) { json() }
        // Lets each request set its own time limit (timeout { … } below).
        install(HttpTimeout)
        // expectSuccess stays false, the default: a 404 or a 500 is an answer, not an exception.
    }

    override suspend fun get(
        url: String,
        params: Map<String, String>,
        headers: Map<String, String>,
        timeLimit: Duration,
    ): ProbeResult = probe {
        client.get(url) {
            params.forEach { (name, value) -> parameter(name, value) } // encoded into the query
            headers.forEach { (name, value) -> header(name, value) }
            timeout { requestTimeoutMillis = timeLimit.inWholeMilliseconds }
        }
    }

    override suspend fun post(
        url: String,
        message: ProbeMessage,
        headers: Map<String, String>,
        timeLimit: Duration,
    ): ProbeResult = probe {
        client.post(url) {
            headers.forEach { (name, value) -> header(name, value) }
            timeout { requestTimeoutMillis = timeLimit.inWholeMilliseconds }
            contentType(ContentType.Application.Json)
            setBody(MessageBody(message.text, message.sentAt.toString()))
        }
    }

    // Sends the request and turns everything that can happen into a ProbeResult. The one
    // exception that passes through is a CancellationException: the screen went away.
    private suspend fun probe(send: suspend () -> HttpResponse): ProbeResult = try {
        val response = send()
        ProbeResult.Answered(response.status.value, readBody(response))
    } catch (e: HttpRequestTimeoutException) { // the whole request took too long; like the next
        // two, it's an IOException too, so the timeouts come before the IOException below
        ProbeResult.TimedOut
    } catch (e: ConnectTimeoutException) { // no connection in time
        ProbeResult.TimedOut
    } catch (e: SocketTimeoutException) { // the server went quiet mid-answer
        ProbeResult.TimedOut
    } catch (e: IOException) { // everything else the network does: no host, refused, offline
        ProbeResult.Unreachable(e.message ?: e.toString())
    } catch (e: CancellationException) { // the screen went away: let the coroutine end
        throw e
    } catch (e: Exception) { // a URL the service let through, but Ktor or the engine refuses
        ProbeResult.Unreachable(e.message ?: e.toString())
    }

    // A JSON body, indented for the screen; any other body as it came. A body that says it's
    // JSON but isn't comes as it came, too.
    private suspend fun readBody(response: HttpResponse): String {
        val isJson = response.contentType()?.match(ContentType.Application.Json) == true
        if (!isJson) return response.bodyAsText()
        return try {
            indented.encodeToString(JsonElement.serializer(), response.body<JsonElement>())
        } catch (e: ContentConvertException) {
            response.bodyAsText()
        }
    }

    // The JSON a POST sends. It lives here, in the adapter, so ProbeMessage carries no JSON
    // annotations (as JsonLines does for the log).
    @Serializable
    private class MessageBody(val text: String, val sentAt: String)

    private companion object {
        val indented = Json { prettyPrint = true }
    }
}

    // Leaving the screen clears the ViewModel, which cancels viewModelScope, and with it the
    // request on its way.
    private fun send(method: String, call: suspend () -> ApiTestResult) {
        request?.cancel() // the newest request wins
        _uiState.value = ApiTestUiState(sending = true) // the last answer goes: it was for another request
        request = viewModelScope.launch {
            _uiState.value = shown(method, call())
        }
    }

    private fun shown(method: String, result: ApiTestResult): ApiTestUiState = when (result) {
        is ApiTestResult.Success ->
            ApiTestUiState(outcome = "$method · ${result.status} · success", detail = shortened(result.body))
        is ApiTestResult.HttpError ->
            ApiTestUiState(outcome = "$method · HTTP error ${result.status}", failed = true, detail = shortened(result.body))
        is ApiTestResult.TimedOut ->
            ApiTestUiState(outcome = "$method · no answer within ${result.limit.inWholeSeconds} s", failed = true)
        is ApiTestResult.Unreachable ->
            ApiTestUiState(outcome = "$method · couldn't reach the server", failed = true, detail = result.reason)
        is ApiTestResult.InvalidUrl ->
            ApiTestUiState(outcome = "Enter a URL that starts with http:// or https://", failed = true)
    }

    // A web page can be megabytes long; the screen shows the start of it.
    private fun shortened(body: String): String =
        if (body.length <= SHOWN_CHARS) body
        else body.take(SHOWN_CHARS) + "\n… and ${body.length - SHOWN_CHARS} more characters"

    companion object {
        // What the URL field starts with: an echo service that answers GET and POST with JSON
        // describing the request it got, headers and body included.
        const val SUGGESTED_URL = "https://httpbin.org/anything"
        const val SHOWN_CHARS = 4000
    }
}

// Stateful: owns the filter text and connects the shared ViewModel to the content below. The
// main screen: every feature starts here, and the device screen is one tap away.
@Composable
fun DeviceListScreen(
    onDeviceClick: (Device) -> Unit,
    onApiTest: () -> Unit,
    viewModel: DeviceListViewModel = koinViewModel(),
) {
    var filter by rememberSaveable { mutableStateOf("") }
    val state by viewModel.uiState.collectAsStateWithLifecycle()

    // Back from Settings (or anywhere else): the permission and the status may have changed.
    LifecycleEventEffect(Lifecycle.Event.ON_RESUME) {
        viewModel.refreshPermission()
        viewModel.refreshStatus()
    }

    DeviceListContent(
        filter = filter,
        onFilterChange = { filter = it },
        bluetooth = state.bluetooth,
        isScanning = state.scan is ScanState.Scanning,
        devices = when (val scan = state.scan) {
            ScanState.Idle -> null
            is ScanState.Scanning -> scan.found
            is ScanState.Finished -> scan.found
        },
        onScan = { viewModel.startScan(filter) },
        onStop = viewModel::stopScan,
        onAllow = viewModel::requestPermission,
        onOpenSettings = viewModel::openSettings,
        onDeviceClick = onDeviceClick,
        phoneStatus = state.phoneStatus,
        onRefreshStatus = viewModel::refreshStatus,
        monitor = { MonitorSection() },
        onApiTest = onApiTest,
    )

    state.errorMessage?.let { message ->
        AlertDialog(
            onDismissRequest = viewModel::errorShown,
            confirmButton = { TextButton(onClick = viewModel::errorShown) { Text("OK") } },
            title = { Text("Scan failed") },
            text = { Text(message) },
        )
    }
}

        val b = binding ?: return
        val isScanning = state.scan is ScanState.Scanning
        val devices = when (val scan = state.scan) {
            ScanState.Idle -> null
            is ScanState.Scanning -> scan.found
            is ScanState.Finished -> scan.found
        }
        b.phoneStatusText.text = state.phoneStatus
        renderPermission(b, state.bluetooth)
        b.scanButton.text = if (isScanning) "Stop" else "Scan"
        b.scanButton.isEnabled = isScanning || state.bluetooth == PermissionStatus.Granted
        b.progress.visibility = if (isScanning) View.VISIBLE else View.GONE
        b.statusText.text = when {
            isScanning -> "Scanning…"
            devices == null -> "Tap Scan to look for devices."
            devices.isEmpty() -> "No devices found. Try another filter."
            else -> "Devices found: ${devices.size}"
        }
        b.statusText.setTextColor(if (devices?.isEmpty() == true && !isScanning) Color.RED else Color.DKGRAY)
        adapter.submitList(devices.orEmpty())
        renderError(state.errorMessage)
    }

    // The monitor section: every new monitor state ends here.
    private fun renderMonitor(state: MonitorUiState) {
        val b = binding ?: return
        b.monitorSummary.text = state.summary
        b.monitorButton.text = if (state.running) "Stop" else "Start"
        b.recordCountText.text = "Records in the log: ${state.recordCount}"
        b.clearLogButton.isEnabled = state.recordCount > 0
        b.newestRecordsText.text = state.newest.joinToString("\n")
        b.newestRecordsText.visibility = if (state.newest.isEmpty()) View.GONE else View.VISIBLE
        b.monitorProblemText.text = state.problem
        b.monitorProblemText.visibility = if (state.problem == null) View.GONE else View.VISIBLE
    }

    // One message and at most one action per permission status.
    private fun renderPermission(b: FragmentDeviceListBinding, status: PermissionStatus) {
        val (message, action) = when (status) {
            PermissionStatus.Granted -> "Bluetooth permission: allowed" to null
            PermissionStatus.NotRequested ->
                "Device Monitor needs Bluetooth permission to find nearby devices." to "Allow Bluetooth"
            PermissionStatus.Denied ->
                "Bluetooth permission was denied. Scanning needs it to find nearby devices." to "Ask again"
            PermissionStatus.PermanentlyDenied ->
                "Bluetooth permission is off. You can turn it on in Settings." to "Open Settings"
            PermissionStatus.Restricted ->
                "Bluetooth is restricted on this device, so scanning isn't available." to null
        }
        b.permissionText.text = message
        val blocked = status != PermissionStatus.Granted && status != PermissionStatus.NotRequested
        b.permissionText.setTextColor(if (blocked) Color.RED else Color.DKGRAY)
        b.permissionButton.visibility = if (action == null) View.GONE else View.VISIBLE
        b.permissionButton.text = action
        b.permissionButton.setOnClickListener {
            if (status == PermissionStatus.PermanentlyDenied) {
                viewModel.openSettings()
            } else {
                viewModel.requestPermission()
            }
        }
    }

    private fun renderError(message: String?) {
        if (message == null) {
            errorDialog?.dismiss()
            errorDialog = null
        } else if (errorDialog == null) {
            errorDialog = AlertDialog.Builder(requireContext())
                .setTitle("Scan failed")
                .setMessage(message)
                .setPositiveButton("OK") { _, _ -> viewModel.errorShown() }
                .setOnCancelListener { viewModel.errorShown() }
                .show()
        }
    }

        super.viewWillAppear(animated)
        viewModel.refreshStatus()
        observation?.cancel()
        observation = Task {
            for await state in viewModel.uiState {
                render(state)
            }
        }
        monitorObservation?.cancel()
        monitorObservation = Task {
            for await state in monitorViewModel.uiState {
                renderMonitor(state)
            }
        }
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        observation?.cancel()
        observation = nil
        monitorObservation?.cancel()
        monitorObservation = nil
    }

    // The one place that touches views: every new state ends here. The text field owns
    // its own text, so render() never sets it.
    private func render(_ state: DeviceListUiState) {
        let isScanning = state.scan is ScanStateScanning
        // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
        let devices: [Device]? = switch onEnum(of: state.scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
        phoneStatusLabel.text = state.phoneStatus
        renderPermission(state.bluetooth)
        scanButton.configuration?.title = isScanning ? "Stop" : "Scan"
        scanButton.isEnabled = isScanning || state.bluetooth == .granted
        if isScanning { spinner.startAnimating() } else { spinner.stopAnimating() }
        spinner.isHidden = !isScanning
        if isScanning {
            statusLabel.text = "Scanning…"
        } else if let devices {
            statusLabel.text = devices.isEmpty
                ? "No devices found. Try another filter."
                : "Devices found: \(devices.count)"
        } else {
            statusLabel.text = "Tap Scan to look for devices."
        }
        statusLabel.textColor = devices?.isEmpty == true && !isScanning ? .systemRed : .label

        devicesById = Dictionary(uniqueKeysWithValues: (devices ?? []).map { ($0.id, $0) })
        var snapshot = NSDiffableDataSourceSnapshot<Int, String>()
        snapshot.appendSections([0])
        snapshot.appendItems((devices ?? []).map(\.id))
        dataSource.apply(snapshot, animatingDifferences: true)
        renderError(state.errorMessage)
    }

    // The monitor section: every new monitor state ends here.
    private func renderMonitor(_ state: MonitorUiState) {
        monitorSummaryLabel.text = state.summary
        monitorButton.configuration?.title = state.running ? "Stop" : "Start"
        recordCountLabel.text = "Records in the log: \(state.recordCount)"
        clearLogButton.isEnabled = state.recordCount > 0
        newestRecordsLabel.text = state.newest.joined(separator: "\n")
        newestRecordsLabel.isHidden = state.newest.isEmpty
        monitorProblemLabel.text = state.problem
        monitorProblemLabel.isHidden = state.problem == nil
    }

    // One message and at most one action per permission status. SKIE makes the Kotlin enum a
    // Swift enum, so this switch is exhaustive.
    private func renderPermission(_ status: PermissionStatus) {
        let (message, action): (String, String?) = switch status {
        case .granted: ("Bluetooth permission: allowed", nil)
        case .notRequested: ("Device Monitor needs Bluetooth permission to find nearby devices.", "Allow Bluetooth")
        case .denied: ("Bluetooth permission was denied. Scanning needs it to find nearby devices.", "Ask again")
        case .permanentlyDenied: ("Bluetooth permission is off. You can turn it on in Settings.", "Open Settings")
        case .restricted: ("Bluetooth is restricted on this device, so scanning isn't available.", nil)
        }
        permissionLabel.text = message
        permissionLabel.textColor = switch status {
        case .granted: .secondaryLabel
        case .notRequested: .label
        case .denied, .permanentlyDenied, .restricted: .systemRed
        }
        permissionButton.configuration?.title = action
        permissionButton.isHidden = action == nil
    }

    private func renderError(_ message: String?) {
        guard let message, presentedViewController == nil else { return }
        let alert = UIAlertController(title: "Scan failed", message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "OK", style: .default) { [weak self] _ in
            self?.viewModel.errorShown()
        })
        present(alert, animated: true)
    }

    func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        tableView.deselectRow(at: indexPath, animated: true)
        guard let deviceId = dataSource.itemIdentifier(for: indexPath), let device = devicesById[deviceId] else { return }
        // The detail screen gets the whole device: it needs all of it to connect.
        navigationController?.pushViewController(DeviceDetailViewController(device: device), animated: true)
    }
