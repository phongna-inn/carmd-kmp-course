Kotlin↔Swift with SKIE

~1.5 h · +0.5 h per extra UI track Milestone: m04 iOS observes the ViewModel through SKIE Prereq: 08
Why this matters: in m03, iOS reaches the shared ViewModel through a bridge you wrote by hand: a 23-line Kotlin watcher, a 29-line observer on SwiftUI, and as? casts that say nothing when Kotlin adds a case. The team's app will have many flows and many sealed types, and each one would need more of that code. Today a compiler plugin, SKIE, writes the bridge for you: Swift iterates the StateFlow with for await, and switches over the sealed state with a switch the compiler checks. The bridge files are deleted. That's milestone m04. It has a price, which you also learn today: SKIE ties the project to the Kotlin versions it supports.

Primary source SKIE's Flows page, then its Sealed classes page. Both are short. Read them after section 1.

Tracks Only iOS code changes in this lesson. On both Android tracks the one change is the root build file (the Kotlin version), and the Android sources stay as they are. The SwiftUI and UIKit screens change in section 3. Each excerpt shows only the lines its notes explain, and the complete files are in Full files at the end.

1. What SKIE generates

SKIE (from Touchlab) is a Kotlin compiler plugin. Lesson 05 showed that Swift sees Kotlin through the Objective-C header that Kotlin/Native writes into Shared.framework, and Lesson 08 showed what that header loses: a StateFlow's type argument, and the fact that a sealed interface has exactly three cases. SKIE runs while Gradle builds the framework. It leaves the header's declarations alone, and adds Swift code into the same framework that gives back what the header lost:

  • Shared ViewModel and its UI state
  • iOS
KotlinWithout SKIE (m03)With SKIE (m04)
Flow<T>, StateFlow<T>an untyped protocol; no for awaitSkieSwiftStateFlow<T>: an AsyncSequence of T, with a typed value. "SKIE automatically converts Flows to custom Swift classes that implement AsyncSequence" (Flows)
sealed class or interfacea protocol plus classes; cast with as?onEnum(of:) returns a generated Swift enum, so a switch over it is exhaustive (Sealed classes)
suspend funa completion handler, or an async function the interop page calls experimentala Swift async function that supports cancellation (the app has none yet)

Cancellation works in both directions. When the Swift Task running a for await loop is cancelled, SKIE cancels the Kotlin collection behind it. The other way round, "if the Flow is canceled from Kotlin, SKIE automatically cancels the Swift task that collects the Flow" (Flows). That's everything StateFlowWatcher and Watch did by hand.

From TypeScriptSKIE is a code-generation step built into the compiler, a bit like GraphQL Codegen writing typed TypeScript from a schema on every build. The Kotlin you write doesn't change: only what the other language sees does. for await (const s of stream) in JS is for await s in stream in Swift.

2. Install it, and pin Kotlin

SKIE is a Gradle plugin. You declare it once in the root build file, with its version, and apply it in the shared module. On m03's Kotlin 2.4.21, that fails before anything compiles:

Gotcha · SKIE supports a fixed list of Kotlin versions With SKIE 0.10.15 (the version this course uses) added to the m03 project, every Gradle command failed while configuring :shared: 
Error: SKIE 0.10.15 does not support Kotlin 2.4.21.
  Supported versions are: [2.0.0, 2.0.10, …, 2.4.0, 2.4.10, 2.4.20].
  Check if you have the most recent version of SKIE and if so, please wait for the SKIE developers to add support for this Kotlin version.
  New Kotlin versions are usually supported within a few days after they are released.
  …
  To proceed with the compilation, please remove or explicitly disable SKIE by adding 'skie { isEnabled = false }' to your Gradle configuration.
A compiler plugin hooks into the compiler's internals, which can change in any Kotlin release, so each SKIE release supports an exact list of Kotlin versions, the one the error prints. From m04 on, the course uses Kotlin 2.4.20. The rule for the team's app: check SKIE's supported versions before you bump Kotlin, and move the two together. If you're ever blocked, the message tells you the way out: skie { isEnabled = false } builds without SKIE (and without anything it generates, so the Swift code that uses it stops compiling).

So the root build file changes in two ways: every Kotlin plugin goes from 2.4.21 to 2.4.20, and SKIE is declared. Your Android track decides which Kotlin plugins the file has:

  1. Every Kotlin plugin moves together. The Compose compiler and serialization plugins ship with Kotlin and carry its version number, so they go to 2.4.20 with it.
  2. apply false in the root, a bare id in the module: the root file declares the plugin and its version for the whole build without applying it there, and shared applies it, taking the version from the root. That's the same split every other plugin in the project already uses. androidApp doesn't apply SKIE: it only touches the iOS framework.
  3. The first build after the change is slower: Gradle downloads the SKIE plugin, and Kotlin/Native downloads its 2.4.20 toolchain if it isn't installed yet (Lesson 05's build path).

Then delete the bridge: shared/src/iosMain/…/StateFlowWatcher.kt on both iOS tracks, and iosApp/iosApp/DeviceListObserver.swift on SwiftUI. ViewModelResolver.kt and ViewModelOwner.swift stay, because SKIE converts types and doesn't own anything: clearing ViewModels is still your job on iOS (Lesson 08, section 5).

Expected build noise. With SKIE applied, every Gradle build also prints eight or nine lines of the form Configuration '…' was resolved during configuration time. In the Xcode build they name skieSubPlugin, skieCompilerPlugin and others; the Android build's name Kotlin and Android configurations, but they still come from SKIE (the same build on Kotlin 2.4.20 without SKIE prints none). When the framework is rebuilt, the Xcode build also prints SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder". None of these come from our code, and they aren't compiler warnings. The course's "no warnings" rule is about w: and warning: lines from our Kotlin and Swift.

Analytics. Each iOS framework build also runs a skieUploadAnalytics… task. SKIE collects build statistics that its documentation calls "non-identifying" (versions, durations, hardware, project structure, git statistics, and its own settings) and uploads them to Touchlab (SKIE Analytics). If your team's policy forbids that, skie { analytics { enabled.set(false) } } in shared/build.gradle.kts turns off both collecting and uploading. The course leaves the default on.

3. The iOS screens: for await and onEnum

Lesson 08 split the iOS work into two jobs: own the ViewModel, and observe its state. SKIE replaces only the observing half. The diagram is Lesson 08's, after the change:

  • Shared ViewModel
  • iOS
  1. @State private var owner = ViewModelOwner(): the screen now holds the owner itself, and DeviceListObserver is gone. Creating an owner is cheap (an empty store), which is what Apple asks of a @State default. That fixes the shortcut Lesson 08 pointed out, where the observer's init created the ViewModel and started watching.
  2. owner.viewModel(…) in body runs on every render, and always returns the same instance: the store creates the ViewModel on the first call and hands it back after that (Lesson 08, section 5). One ViewModel per screen, created on the first render, cleared when the owner goes.
  3. .task { for await newState in viewModel.uiState { … } }: with SKIE, uiState is an AsyncSequence of DeviceListUiState, so the loop needs no cast. SwiftUI starts the task before the view appears and cancels it "at some point after the view disappears" (task(name:priority:file:line:_:)). Cancelling it ends the loop, which cancels the Kotlin collection. That's SwiftUI's collectAsStateWithLifecycle.
  4. .task runs again when you come back from the detail screen (Lesson 07's gotcha). Here that's harmless, because the task only observes. The scan lives in the ViewModel, and a new loop gets the latest state first.
  5. self.state ?? viewModel.uiState.value: until the loop delivers its first value, body reads the flow's current value, which SKIE now types as DeviceListUiState. A StateFlow always has one. The @State property is what makes SwiftUI re-render: each assignment in the loop updates the view.
  6. Compiled in Swift 6 mode with no warnings. The Sendable errors from Lesson 08's gotcha don't appear with SKIE's types.
  1. observation = Task { for await state in viewModel.uiState { render(state) } } replaces the watch. A UIViewController is @MainActor, and a Task inherits its caller's actor (Lesson 07, section 3), so render runs on the main thread.
  2. Cancel in viewDidDisappear: cancelling the task ends the loop and the Kotlin collection, as watch?.cancel() did in m03. While the detail screen is pushed, nothing renders into hidden views; the ViewModel keeps scanning, and when the list reappears, the new loop gets the latest state first.
  3. The Task captures self strongly, unlike m03's [weak self] callback. That's fine here, because viewDidDisappear always cancels it, which ends the loop and releases self. Without that cancel, the loop would keep the view controller alive, and its ViewModel would never be cleared. observation?.cancel() before each new Task makes sure an old loop is never left running.
  4. render(viewModel.uiState.value) at the end of viewDidLoad: SKIE types value, so the first frame needs no watcher either.

The second half of the change is the sealed state. Swift used to see ScanState as a protocol, so m03 cast with as? and had a fallback for "none of these". With SKIE, onEnum(of:) turns a ScanState into a Swift enum, and a switch over it has to name every case:

Here is what SKIE generated for ScanState. You never edit this file, and it isn't in your source tree: it's rebuilt with the framework.

  1. The casts didn't disappear; they moved into generated code. onEnum(of:) is the same as? chain m03 wrote by hand, generated from the Kotlin sealed interface on every build. So it always lists exactly the subclasses Kotlin declares.
  2. The enum is what makes your switch checked. It has one case per subclass, each carrying the typed Kotlin object (case .scanning(let scanning) binds a ScanStateScanning, so scanning.found works). Add a fourth Kotlin case and the enum gains a fourth case on the next build, so every switch without it stops compiling. m03's as? chain returned nil for the new case and said nothing.
  3. fatalError covers a subclass that isn't in the list. As the message says, that shouldn't happen under normal circumstances, because the list is generated from the sealed type. (If some subclasses were hidden from Swift, SKIE would generate an .else case instead: Sealed classes.)
  4. isScanning still uses is ScanStateScanning: a yes/no question needs no switch, and the class names from Shared.h still work.

UIKit vs SwiftUI · what changed and whyBoth do the same thing in their own lifecycle: start a for await over uiState when the screen appears, cancel it when it disappears. SwiftUI's .task cancels for you, and UIKit stores the Task and cancels it in viewDidDisappear. Both tracks lost the 23-line Kotlin watcher, SwiftUI also lost its 29-line observer, and both switched from casts to an exhaustive switch.

4. Where Kotlin↔Swift is heading

JetBrains is building Swift export: Kotlin compiled to a Swift API directly, instead of through an Objective-C header. It exports flows "as Swift's AsyncSequence" and maps sealed hierarchies to Swift enums. Today it's in Alpha: "still incomplete, so breaking changes are expected" (Swift export). When it matures, it should give you what SKIE gives today without a third-party compiler plugin, and with it the version pinning goes away. Until then, the course uses SKIE.

Other options you'll meet in KMP codebases: KMP-NativeCoroutines (annotate a flow or a suspend function, and its plugin generates a Kotlin "native version" that its Swift packages turn into an async function, an AsyncSequence, a Combine publisher or an RxSwift observable) and KMP-ObservableViewModel, which JetBrains' Compose Multiplatform ViewModel page recommends for using shared ViewModels from SwiftUI. Between them they cover the same two jobs as Lesson 08: owning and observing.

5. What actually happens

We built m04 (Kotlin 2.4.20, SKIE 0.10.15, Lifecycle 2.11.0, coroutines 1.11.0, AGP 9.4.1, Xcode 26.2) and ran it on the Android 16 emulator and the iOS 26.2 simulator. Both apps behave exactly as m03: rows arrive one by one under "Scanning…", the status reads "Devices found: 5" at 3 s, the filter fail shows the "Scan failed" dialog, and leaving the iOS list screen clears its ViewModel. Gotcha · Shared.h looks unchanged Looking for SKIE's types in Shared.h, you'll find uiState declared exactly as before: id<SharedKotlinx_coroutines_coreStateFlow>. SKIE adds its own classes to the header (SkieKotlinStateFlow and friends), but the typed property is in Shared.framework/Headers/Shared.apinotes, a file the Swift compiler reads next to the header, where uiState's type is SharedSkieKotlinStateFlow<SharedDeviceListUiState *>. The generated Swift (onEnum, SkieSwiftStateFlow) is under shared/build/skie/…/swift/generated/. When Swift and the header disagree, look there.

Retrieval checks

Answer from memory, without scrolling up.

What does SKIE turn a Kotlin StateFlow<T> into?

SkieSwiftStateFlow<T> conforms to AsyncSequence, with a typed value. You iterate it with for await, inside .task or a stored Task.

The team bumps Kotlin to a version released yesterday. What's the likely first failure?

SKIE checks the Kotlin version when Gradle configures :shared, and refuses a version it doesn't list, before anything compiles. That's on every Gradle command, so the Android build stops too.

With SKIE in place, which file does iOS still need?

SKIE converts types; it doesn't own anything. Clearing ViewModels is still your job on iOS.

You add a fourth case to Kotlin's ScanState. What happens to m04's Swift switch onEnum(of:)?

SKIE regenerates the enum with a fourth case, and a Swift switch must be exhaustive. Falling to nil silently is what m03's as? chain did. onEnum's fatalError isn't reached: the new case is in its generated list.

The SwiftUI list disappears behind the detail screen. What stops?

SwiftUI cancels the .task, which ends the loop, and SKIE cancels the Kotlin collection. The ViewModel lives on in its owner, so the scan carries on, and the next .task gets the latest state.

Mixed review (interleaved)

SKIE's Swift is compiled into Shared.framework. When you build in Xcode, what produces the framework? (Lesson 05)

The target's first build phase runs ./gradlew :shared:embedAndSignAppleFrameworkForXcode, which builds the framework (and, with SKIE applied, its generated Swift) before Xcode compiles your Swift.

Why must the scan never start in the list's .task? (Lesson 07)

Coming back from the detail screen runs .task again. Observing in it is harmless, because a new loop just reads the latest state. Starting work there would scan again on every return.

iosApp/iosApp/DeviceListView.swift 
import SwiftUI
import Shared

// Stateful: owns the filter text and connects the shared ViewModel to the content below.
struct DeviceListView: View {
    @State private var owner = ViewModelOwner()
    @State private var filter = ""
    @State private var state: DeviceListUiState?

    var body: some View {
        let viewModel: DeviceListViewModel = owner.viewModel(factory: DeviceListViewModel.companion.Factory)
        let state = self.state ?? viewModel.uiState.value
        DeviceListContent(
            filter: $filter,
            isScanning: state.scan is ScanStateScanning,
            devices: devices(in: state.scan),
            onScan: { viewModel.startScan(filter: filter) }
        )
        .alert(
            "Scan failed",
            isPresented: Binding(
                get: { state.errorMessage != nil },
                set: { if !$0 { viewModel.errorShown() } }
            ),
            actions: { Button("OK") {} },
            message: { Text(state.errorMessage ?? "") }
        )
        .task {
            for await newState in viewModel.uiState {
                self.state = newState
            }
        }
    }

    // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
    private func devices(in scan: ScanState) -> [Device]? {
        switch onEnum(of: scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
    }
}

// Stateless: renders whatever it's given, reports events up.
struct DeviceListContent: View {
    @Binding var filter: String
    let isScanning: Bool
    let devices: [Device]?
    let onScan: () -> Void

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            TextField("Device name filter", text: $filter)
                .textFieldStyle(.roundedBorder)
                .autocorrectionDisabled()
            Button(action: onScan) {
                Text("Scan")
                    .frame(maxWidth: .infinity)
            }
            .buttonStyle(.borderedProminent)
            .disabled(isScanning)
            ScanStatus(isScanning: isScanning, devices: devices)
            List(devices ?? [], id: \.id) { device in
                NavigationLink(value: DeviceRoute(id: device.id)) {
                    DeviceRow(device: device)
                }
            }
            .listStyle(.plain)
        }
        .padding()
        .navigationTitle("Device Monitor")
    }

import UIKit
import Shared

final class DeviceListViewController: UIViewController, UITableViewDelegate {
    private let owner = ViewModelOwner()
    private lazy var viewModel: DeviceListViewModel = owner.viewModel(factory: DeviceListViewModel.companion.Factory)
    private var observation: Task<Void, Never>?

    private let filterField = UITextField()
    private let scanButton = UIButton(configuration: .filled())
    private let spinner = UIActivityIndicatorView(style: .medium)
    private let statusLabel = UILabel()
    private let tableView = UITableView()
    private lazy var dataSource = UITableViewDiffableDataSource<Int, String>(tableView: tableView) {
        tableView, indexPath, deviceId in
        let cell = tableView.dequeueReusableCell(withIdentifier: "device", for: indexPath)
        var content = UIListContentConfiguration.subtitleCell()
        if let device = SampleDevices.shared.find(id: deviceId) {
            content.text = device.name
            content.secondaryText = "\(device.id)   \(device.rssi) dBm"
        }
        cell.contentConfiguration = content
        cell.accessoryType = .disclosureIndicator
        return cell
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        title = "Device Monitor"
        navigationController?.navigationBar.prefersLargeTitles = true
        view.backgroundColor = .systemBackground

        filterField.placeholder = "Device name filter"
        filterField.borderStyle = .roundedRect
        filterField.autocorrectionType = .no
        scanButton.configuration?.title = "Scan"
        scanButton.addAction(UIAction { [weak self] _ in
            guard let self else { return }
            viewModel.startScan(filter: filterField.text ?? "")
        }, for: .touchUpInside)
        statusLabel.numberOfLines = 0
        tableView.register(UITableViewCell.self, forCellReuseIdentifier: "device")
        tableView.delegate = self

        let statusRow = UIStackView(arrangedSubviews: [spinner, statusLabel])
        statusRow.spacing = 8
        let stack = UIStackView(arrangedSubviews: [filterField, scanButton, statusRow, tableView])
        stack.axis = .vertical
        stack.spacing = 12
        stack.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(stack)
        NSLayoutConstraint.activate([
            stack.topAnchor.constraint(equalTo: view.layoutMarginsGuide.topAnchor),
            stack.leadingAnchor.constraint(equalTo: view.layoutMarginsGuide.leadingAnchor),
            stack.trailingAnchor.constraint(equalTo: view.layoutMarginsGuide.trailingAnchor),
            stack.bottomAnchor.constraint(equalTo: view.bottomAnchor),
        ])
        render(viewModel.uiState.value)
    }

    // Collect only while on screen, like repeatOnLifecycle(STARTED) on Android.
    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        observation?.cancel()
        observation = Task {
            for await state in viewModel.uiState {
                render(state)
            }
        }
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        observation?.cancel()
        observation = nil
    }

    // The one place that touches views: every new state ends here. The text field owns
    // its own text, so render() never sets it.
    private func render(_ state: DeviceListUiState) {
        let isScanning = state.scan is ScanStateScanning
        // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
        let devices: [Device]? = switch onEnum(of: state.scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
        scanButton.isEnabled = !isScanning
        if isScanning { spinner.startAnimating() } else { spinner.stopAnimating() }
        spinner.isHidden = !isScanning
        if isScanning {
            statusLabel.text = "Scanning…"
        } else if let devices {
            statusLabel.text = devices.isEmpty
                ? "No devices found. Try another filter."
                : "Devices found: \(devices.count)"
        } else {
            statusLabel.text = "Tap Scan to look for devices."
        }
        statusLabel.textColor = devices?.isEmpty == true && !isScanning ? .systemRed : .label

        var snapshot = NSDiffableDataSourceSnapshot<Int, String>()
        snapshot.appendSections([0])
        snapshot.appendItems((devices ?? []).map(\.id))
        dataSource.apply(snapshot, animatingDifferences: true)
        renderError(state.errorMessage)
    }

    private func renderError(_ message: String?) {
        guard let message, presentedViewController == nil else { return }
        let alert = UIAlertController(title: "Scan failed", message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "OK", style: .default) { [weak self] _ in
            self?.viewModel.errorShown()
        })
        present(alert, animated: true)
    }

    func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        tableView.deselectRow(at: indexPath, animated: true)
        guard let deviceId = dataSource.itemIdentifier(for: indexPath) else { return }
        navigationController?.pushViewController(DeviceDetailViewController(deviceId: deviceId), animated: true)
    }
}
